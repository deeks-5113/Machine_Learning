The core idea

Classical programming vs ML

A classical (SDE) program is rules you write by hand. An ML model is rules the machine finds from examples. Same job — spam filtering — two completely different ways of getting there.

👨‍💻 The SDE way

📥 Input text: "buy now, click here"
↓ you hand-write the rule
if (text contains buy/delete/immediately)
↓
→ Spam, else → Not Spam

Works — until someone writes "procure" instead of "purchase". Now you need another rule. And another. Soon you have thousands of if-else rules, and it's still brittle.

vs

🧠 The ML way

📥 Training data: 100s of past emails
↓ model finds the pattern itself
X = email text  →  y = spam / not spam
↓
model learns which patterns mean spam

No one writes the rule. The model is shown labelled examples (input + correct answer) and works out the pattern on its own — that's the heart of ML.

The big split

How ML gets categorized

Every ML problem on the board falls into one of three families — sorted by one question: does your data come with answers attached?

🎯

Supervised Learning

Data has both X (inputs) and y (correct answers). Model learns the mapping X → y.

🧩

Unsupervised Learning

Only X — no answers given. Model finds structure or groups on its own.

🎮

Reinforcement Learning

No fixed dataset — an agent learns by trial, error, and reward.

Family 1

Supervised learning

SL = (X, y) — inputs paired with the correct target. The board's analogy: an intern shadowing doctors.

"Imagine an intern sitting with doctors, looking at hundreds of X-rays. Each one is already labelled — has COVID or doesn't have COVID. After enough of these, the intern starts spotting the pattern themself. Hand them a brand-new X-ray, and they take a guess — that guess is the prediction."

Vocabulary from the board

X → input features
y → target / actual label
ŷ (y-hat) → model's prediction
Training data → X + y shown to the model
SL in one line:
Input + Labels → Target → predict during test

Another task type

Time Series forecasting

Same idea as regression — predicting a number — but with one extra rule: order matters. Each row depends on what came before it in time, so you can't shuffle the rows the way you would for a normal dataset.

Board example — Google's stock price

To predict today's closing price, the features themselves come from the recent past:

f1: prev day lowf2: prev day highf3: 52-week lowf4: 52-week highPrice (y)
28412879221029502865
28652901221029502888
28882910221029502873

Notice the features for "today" are built from yesterday's numbers. That's the whole trick of time series — the past few days become the input, and tomorrow becomes the target.

Why you can't split this randomly

A normal 80/20 split picks rows at random. For time series, that would let the model "see the future" while training — so instead, the split is a clean cut along the calendar:

Train → Jan, Feb, March, April → Test → May, June (the future, unseen)

Train only on the past, test on what comes after — never the other way round. Other examples from the board: sales forecasting, weather prediction, demand planning.

Another task type

Recommendation Systems

The job: given what someone has already watched, bought, or liked, suggest what they'd want next — out of a huge, fixed catalogue of items.

Board example — what should you watch next?

Same catalogue, two different watch histories — and two different suggestions:

User A — watched action / thriller titles

→ Recommended next: more action & thriller releases

User B — watched drama / family titles

→ Recommended next: more drama & family releases

Same model, same catalogue — but the input (watch history) is different for each person, so the output (recommendation) is personalised too.

Why this counts as supervised learning

It looks different from predicting a price or a category, but the underlying shape is the same — X and y pair up, the model is just trained on a different kind of pair:

X → what the user has watched / bought / clicked so far
y → what they watched / bought / clicked next

That (X, y) pair is still labelled data, exactly like the house-price or spam examples — the label here is just "what actually happened next," recorded across millions of real users. Train the model on that history, and it learns to predict the next likely item for a brand-new user too. The one real difference: instead of one number or one category, the output is a ranked shortlist of items from the catalogue.

Family 2

Unsupervised learning

Only X — no y at all. The model isn't told the "right answer"; it just looks for structure. The board's example: Amazon grouping customers without anyone labelling them first.

Family 3

Reinforcement learning

No dataset of (X, y) at all. Instead: an agent acts inside an environment, and gets a reward or punishment for each action — millions of times over, until it learns the best strategy.

From the board "Imagine a couple of ducklings born a week ago. Gradually they start walking — with repeated failures, crashing into potholes — until they can not only walk perfectly but also swim like a champ. What kind of ML best fits this analogy?" → Reinforcement Learning — learning by trial and error, the reward signal shaping behaviour over time.

RL loop, from the maze example on the board

Agent → the self-driving car / the mouse in the maze
Environment → the maze, the road
Reward → +100 for reaching the fruit / cheese
Punishment → −300 for hitting a wall / wrong turn
The agent tries millions of iterations across all possible paths. Paths that lead to reward get reinforced; paths that lead to punishment get avoided. Over time it converges on the best route — no human ever wrote "turn left here."
Before training

The train / test split

From the board's 1000-row car-price table: never let a model train on data it'll later be tested on. Split first, randomly, then train only on one side.

1000 rows → split 80 / 20

Train — 800 rows
Test — 200 rows

The model only ever sees the train split's (X, y) during training. The test split is "unseen data" — held back to check if the model actually generalises, or just memorised.

Worked example: BMW input → unseen
Car: "BMW" (test row) → Model (trained) → Predicted: ₹50,000 vs. Actual: ₹70 Lakhs

A bad gap here is exactly what testing on unseen data is meant to catch — and it's the whole reason we never train and test on the same rows.
