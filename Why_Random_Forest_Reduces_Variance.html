Foundations

What Are We Even Taking the Variance Of?

Start with a decision tree trained on a dataset. Call the dataset D. The trained tree is a FUNCTION — give it any input, it gives you a prediction back. Call that function ƒ̂D.

ƒ̂D(x)

Read this literally, symbol by symbol:

SymbolWhat it means
DThe specific set of training rows we happened to draw. Not "data" in general — this exact table of rows.
ƒ̂DThe tree you get after training on D. Different D → different tree. D is a SUBSCRIPT because the tree itself depends on which dataset trained it.
xONE single, fixed test point. Not the whole test set — literally one row.
ƒ̂D(x)A single number (or class label): what this specific tree predicts for this specific point.

Now the idea everything else rests on: fix x. Let D be random. Imagine redrawing your training set over and over from the real world. Each redraw gives a different tree, and that tree gives a (possibly different) prediction at the SAME fixed point x.

ƒ̂D1(x),    ƒ̂D2(x),    ƒ̂D3(x),    ...
All of these are predictions AT THE SAME POINT x, produced by trees trained on DIFFERENT datasets. The randomness lives entirely in D. x never moves.

Variance, From Its Actual Definition

Before touching trees at all, recall what variance means for ANY random variable X:

Var(X) = E[ (X − E[X])² ]

Read left to right, one piece at a time:

1

E[X] — the average value X takes, if you could repeat the random experiment infinitely many times.

2

X − E[X] — how far ONE particular draw of X landed from that average.

3

(X − E[X])² — square it, so negative and positive deviations don't cancel, and big deviations are punished more than small ones.

4

E[·] — average THAT squared deviation over all the ways the experiment could have gone.

In one sentence: variance is "how far, on average, does one draw of X land from where X usually lands."

Applying It To a Tree, Precisely

Now substitute. Our random variable X is NOT "the data" — it is the PREDICTION at our fixed point x, where the randomness is which D we happened to draw:

X = ƒ̂D(x),     randomness is over D,     x is fixed
VarD[ ƒ̂D(x) ] = ED[ ( ƒ̂D(x) − ED[ƒ̂D(x)] )² ]
The small subscript D under Var and E is not decoration — it tells you exactly WHICH thing is random in this expression. It is NOT saying "average over x." x is nailed down. D is what's shaking. This is the formal version of "how much does the tree's prediction at this one customer swing around, depending on which training set trained it."
Why One Tree Is Unstable

Measuring VarD[ƒ̂D(x)] For a Single Tree

Two training sets differing by exactly one row. Dataset A has a row (Age=31, Income=50K, Default=N). Dataset B has that same row changed to Default=Y.

Fitting a tree on A finds root split Age < 30. Fitting on B finds Age < 33 — one flipped label was enough to nudge the threshold search. Now evaluate both trees at x=31:

ƒ̂A(31): 31 ≥ 30 ⇒ goes right ⇒ predicts N
ƒ̂B(31): 31 < 33 ⇒ goes left ⇒ predicts Y
One row out of eight flipped the prediction entirely. Not a fluke — it's structural: the root split is chosen by comparing candidate thresholds on whatever rows happen to be in D, and once the root changes, every node below it inherits a DIFFERENT subset of rows, so every split below can change too. The disagreement cascades.

Now let's actually measure it, not just argue about it

Train 300 separate trees, each on its OWN freshly-drawn 120-row dataset Dm, and record each tree's prediction at the SAME point x0=4.0.

import numpy as np
from sklearn.tree import DecisionTreeRegressor

rng = np.random.default_rng(42)

def true_function(x):
    return 5*np.sin(x) + 0.3*x**1.5          # the real, unknown relationship

def generate_pool(n, rng):
    X = rng.uniform(0, 10, size=n)
    noise = rng.normal(0, 1.2, size=n)
    y = true_function(X) + noise
    return X.reshape(-1,1), y

pool_X, pool_y = generate_pool(50000, rng)     # a huge "population" to draw fresh D's from
x0 = np.array([[4.0]])                         # ONE fixed test point
n_train = 120
M = 300                                         # number of DIFFERENT datasets D we try

single_tree_preds = np.zeros(M)
for m in range(M):
    idx = rng.choice(len(pool_X), size=n_train, replace=False)
    D_X, D_y = pool_X[idx], pool_y[idx]         # this IS one random D

    tree = DecisionTreeRegressor(random_state=int(rng.integers(1e9)))
    tree.fit(D_X, D_y)
    single_tree_preds[m] = tree.predict(x0)[0]  # f_hat_D(x0) for this D

var_single = single_tree_preds.var(ddof=1)
Real executed output
Mean of single-tree predictions across 300 datasets: -1.4836
Var_D[ single tree(x0) ] = 1.6032
The true value at x0=4 is −1.384. The average prediction across 300 trees, −1.4836, sits close to it — bias is small, as expected for a deep, unrestricted tree. But the variance, 1.6032, is large relative to the problem's scale — individual predictions genuinely swing a lot depending on which 120 rows happened to train that particular tree. This IS our measured VarD[ƒ̂D(x0)] for one tree.
Building the Sum

What T1, T2, ..., TB Actually Mean

This is exactly the notation ambiguity worth killing completely before going further.

Tb(x)
SymbolWhat it means
TbThe b-th tree in an ensemble of B trees, each trained on its OWN bootstrap resample.
Tb(x)A SINGLE NUMBER: what tree b predicts at our one fixed point x. Not a dataset. Not a tree structure. A prediction — a scalar.

The randomness in Tb(x) comes from WHICH ROWS happened to land in tree b's bootstrap sample. So T1(x), T2(x), ..., TB(x) are B NUMBERS — B different guesses at the value of x's target, one guess per tree, all made at the same fixed x.

ƒ̂RF(x) = (1/B) ∑b=1B Tb(x)
This is just the plain arithmetic mean of those B numbers. Nothing more exotic than averaging B ordinary numbers together.

Var(a+b), Derived From Scratch

Before any summation notation, do the two-tree case by hand, expanding directly from the definition above. Let a = T1(x) and b = T2(x) — just TWO random variables, each one tree's prediction at our fixed x, over the randomness of which bootstrap sample trained it.

Var(a+b) = E[ ((a+b) − E[a+b])² ]

Since E[a+b] = E[a]+E[b] (expectation of a sum is the sum of expectations — always true, no independence needed):

= E[ ((a−E[a]) + (b−E[b]))² ]

Expand the square (u+v)² = u²+v²+2uv, with u = a−E[a] and v = b−E[b]:

= E[(a−E[a])²] + E[(b−E[b])²] + 2·E[(a−E[a])(b−E[b])]

The first term is Var(a) by definition. The second is Var(b). The third has a name — the COVARIANCE of a and b:

Cov(a,b) ≡ E[(a−E[a])(b−E[b])]
Var(a+b) = Var(a) + Var(b) + 2·Cov(a,b)
What Cov(a,b) means here, concretely: if tree 1 and tree 2 tend to be wrong in the SAME direction together (both too high when the truth is low, say), Cov(a,b)>0 and it ADDS to the total variance. If they err in unrelated directions, Cov(a,b)≈0 and it contributes nothing. This one term is the entire mathematical reason correlation between trees matters.

Var(cX), Also Derived

We also need: if X is a random variable and c is a plain constant, what is Var(cX)? We'll need this because averaging B trees means multiplying the SUM by the constant c=1/B.

Var(cX) = E[(cX − E[cX])²] = E[(cX − cE[X])²] = E[c²(X−E[X])²] = c²·E[(X−E[X])²]
Var(cX) = c²·Var(X)

From B=2 to B=3, By Hand

So the pattern is visible before jumping to any summation symbol:

Var(T1+T2+T3) = Var( (T1+T2) + T3 )

Apply the two-variable rule just derived, treating (T1+T2) as one variable and T3 as the other:

= Var(T1+T2) + Var(T3) + 2·Cov(T1+T2, T3)

Expand Var(T1+T2) using the same rule again, and expand the covariance term using the fact that covariance distributes over sums (the identical expansion trick, applied to Cov instead of Var):

= [ Var(T1)+Var(T2)+2Cov(T1,T2) ] + Var(T3) + 2[ Cov(T1,T3)+Cov(T2,T3) ]

Collect terms:

= Var(T1)+Var(T2)+Var(T3) + 2[ Cov(T1,T2)+Cov(T1,T3)+Cov(T2,T3) ]
Look at the pattern: three individual variance terms (one per tree), plus every DISTINCT PAIR of trees contributing 2× their covariance. With 3 trees there are exactly 3 distinct pairs: (1,2), (1,3), (2,3) — never a pair counted twice, never a tree paired with itself.

The General Sum, For B Trees

The pattern from B=3 continues exactly the same way for any B: one variance term per tree, plus 2× the covariance of every distinct pair. "Every distinct pair" is what the notation ∑i<j means — sum over all pairs (i,j) with i strictly less than j, so each pair is counted exactly once.

Var( ∑b=1B Tb ) = ∑b=1B Var(Tb)  +  2∑i<j Cov(Ti,Tj)
This is NOT a new rule — it is exactly the B=2 and B=3 results just verified by hand, written compactly so we don't re-expand by hand for every new B.

Now bring in Var(cX) with c=1/B, applied to our actual forest average:

ƒ̂RF(x) = (1/B) ∑b=1B Tb(x)
Var( ƒ̂RF(x) ) = Var( (1/B)∑Tb ) = (1/B)² · Var( ∑b=1BTb )
= (1/B²) [ ∑b=1BVar(Tb) + 2∑i<jCov(Ti,Tj) ]
The Two Assumptions, Justified

Why Does Every Tree Have the SAME Variance σ²?

This is not a law of nature — it's an ASSUMPTION, exactly like the "identically distributed" part of "i.i.d." in basic statistics. It deserves a real reason, not just a declaration.

The reason: every tree is built by the identical random PROCESS

Look at what actually differs between T1 and T2 inside a Random Forest:

What's the SAME for every treeWhat DIFFERS between trees
Algorithm (CART), impurity criterion (Gini/entropy)WHICH rows got drawn into its bootstrap sample
Hyperparameters (max_depth, min_samples_leaf, etc.)WHICH features got randomly offered at each split
Bootstrap sample SIZE (n draws, with replacement)The resulting tree structure, as a consequence
The underlying population/dataset D they're all drawing from—
Tree 7 and Tree 13 are generated by EXACTLY the same recipe — only the random numbers used inside that recipe differ. There is no reason baked into the algorithm that tree #7 should be systematically more or less variable than tree #13. Relabeling which tree is "number 7" and which is "number 13" changes nothing about the process — this property is called exchangeability. Exchangeable random variables, by definition, share the same distribution — same mean, same variance. That is the actual justification for Var(Tb)=σ² for every b: it follows from the trees being generated by one identical, symmetric random procedure, not from anything we're hoping is true.

Don't just trust the argument — check it against real trees

If "every tree has the same variance" is really true, then if we look at ONE SPECIFIC tree-slot (say, always "the 5th tree trained") across many repeated outer experiments, its variance across those repeats should be roughly the SAME as the 12th tree-slot's variance, the 30th tree-slot's, and so on — because nothing distinguishes slot 5 from slot 12 except an arbitrary label.

indiv_tree_preds = np.zeros((M, B))     # M=300 outer experiments, B=30 trees each

for m in range(M):
    idx = rng.choice(len(pool_X), size=n_train, replace=False)
    D_X, D_y = pool_X[idx], pool_y[idx]
    for b in range(B):
        boot_idx = rng.choice(n_train, size=n_train, replace=True)
        bx, by = D_X[boot_idx], D_y[boot_idx]
        t = DecisionTreeRegressor(random_state=int(rng.integers(1e9)))
        t.fit(bx, by)
        indiv_tree_preds[m, b] = t.predict(x0)[0]     # T_b(x0) for this D_m

# variance of tree-SLOT b, across the 300 outer experiments — one number per slot
per_tree_var = indiv_tree_preds.var(axis=0, ddof=1)

What Correlation Actually Is, and Why Cov = ρσ²

Step 1 — the problem covariance has, on its own

Cov(a,b) carries UNITS. If predictions are measured in rupees, Cov(a,b) is measured in rupees². That makes a raw covariance number impossible to interpret in isolation — is Cov=50 "highly correlated"? It depends entirely on the scale of the problem. A Cov of 50 might mean near-perfect agreement for a small-scale target, or almost nothing for a target that naturally varies in the thousands.

We want a number that says "how related are a and b" WITHOUT depending on the units or scale of a and b. That number is correlation.

Step 2 — fixing the units problem by rescaling

Divide the covariance by the standard deviations of both variables — this cancels the units exactly, the same way dividing a length in cm by a length in cm gives you a pure, unitless ratio.

Corr(a,b) = Cov(a,b) / √( Var(a)·Var(b) )

Why the square root of the PRODUCT of both variances specifically? Var(a) has units of a², Var(b) has units of b². Their product has units of a²b². Taking the square root gives units of a·b — exactly matching Cov(a,b)'s own units. Dividing two quantities with identical units always leaves something unitless.

Step 3 — proving correlation is always between −1 and 1 (not just asserting it)

This follows directly from a fact we already know: variance can never be negative, because it's defined as an expectation of a SQUARED quantity. Let σa=√Var(a) and σb=√Var(b). Apply this fact to the new random variable (a/σa − b/σb):

Var( a/σa − b/σb ) ≥ 0     (any variance is ≥ 0, always, no exceptions)

Expand the left side using the Var(a+b) rule already derived (with b replaced by −b/σb, noting Var(cX)=c²Var(X) from before means Var(a/σa)=Var(a)/σa²=1, and similarly Var(b/σb)=1):

Var(a/σa) + Var(b/σb) − 2·Cov(a/σa, b/σb) ≥ 0
1 + 1 − 2·Corr(a,b) ≥ 0     (since Cov(a/σa,b/σb) = Cov(a,b)/(σaσb) = Corr(a,b), by definition)
2 − 2·Corr(a,b) ≥ 0  ⇒  Corr(a,b) ≤ 1

Run the identical argument with Var(a/σa + b/σb) ≥ 0 instead, and the sign on the covariance term flips, giving Corr(a,b) ≥ −1.

So −1 ≤ ρ ≤ 1 is not an arbitrary convention someone chose — it falls directly out of the one fact that variance can never be negative, applied to a cleverly rescaled combination of a and b.

Step 4 — now substitute Var(Ti)=Var(Tj)=σ² into the correlation formula

Recall the general definition from Step 2, applied specifically to two trees Ti and Tj:

Corr(Ti,Tj) = Cov(Ti,Tj) / √( Var(Ti)·Var(Tj) )

We just spent the entire previous section justifying Var(Ti) = Var(Tj) = σ². Substitute both:

√( Var(Ti)·Var(Tj) ) = √( σ² · σ² ) = √( σ⁴ )

And √(σ⁴) = σ² exactly, because taking the square root of something raised to the 4th power always gives that something raised to the 2nd power (assuming σ²>0, which it always is for a genuinely random prediction):

√( Var(Ti)·Var(Tj) ) = σ²

So the correlation formula simplifies to:

ρ = Cov(Ti,Tj) / σ²

Multiply both sides by σ² to isolate the covariance:

Cov(Ti,Tj) = ρσ²
This is the ENTIRE derivation of that one line — it is nothing but "divide, then multiply back," made possible specifically because we already justified that both trees share the same σ². If the two trees had DIFFERENT variances σi² and σj², this step would instead give Cov(Ti,Tj) = ρσiσj — the equal-variance assumption is precisely what collapses that into the clean ρσ² form used in the final formula.

Step 5 — what ρ means in plain language, then check it against real trees

ρ=1 means two trees always move in perfect lockstep — whenever one overpredicts, the other overpredicts by a proportional amount, always. ρ=0 means knowing one tree's error tells you nothing about the other's. ρ=0.44, say, is somewhere in between: a real, moderate tendency for two trees (both descended from bootstrap resamples of the same underlying D) to err in similar directions, but far from identical.

corr_matrix = np.corrcoef(indiv_tree_preds, rowvar=False)   # B x B matrix
off_diag = corr_matrix[~np.eye(B, dtype=bool)]           # every distinct pair (i,j)
rho_hat = off_diag.mean()

Putting It Together

The Final Formula, Substituted

Return to where we stopped building the general sum:

Var( ƒ̂RF(x) ) = (1/B²) [ ∑b=1BVar(Tb) + 2∑i<jCov(Ti,Tj) ]

Substitute Var(Tb)=σ² for all B terms in the first sum, and Cov(Ti,Tj)=ρσ² for all pairs in the second sum. The first sum has B identical terms. The second sum has B(B−1)/2 identical terms — that's how many distinct pairs (i,j) with i<j exist among B trees (choose 2 out of B, order doesn't matter):

= (1/B²) [ Bσ² + 2·B(B−1)/2·ρσ² ]

The 2 and the /2 cancel exactly:

= (1/B²) [ Bσ² + B(B−1)ρσ² ]

Factor Bσ² out of both terms inside the brackets, then split the fraction:

= σ² [ B/B² + B(B−1)ρ/B² ] = σ² [ 1/B + ((B−1)/B)·ρ ]

Split (B−1)/B = 1 − 1/B, distribute the ρ, and regroup:

σ²[ 1/B + ρ(1−1/B) ] = σ²[ 1/B + ρ − ρ/B ] = ρσ² + σ²(1/B − ρ/B) = ρσ² + σ²(1−ρ)/B
Var( ƒ̂RF(x) ) = ρσ² + (1−ρ)σ² / B
Every symbol, one final time: σ² = how noisy ONE tree's prediction is by itself (measured: 1.6032 for a plain single tree; the "per-slot" trees inside the bagged experiment measured 1.4776 — close, small differences are sampling noise plus the fact these were trained on bootstrap-of-D rather than fresh D). ρ = how similarly two trees tend to err, because they descend from overlapping data (measured: 0.4446). B = how many trees you average (used: 30).

Verified Against Real, Executed Numbers

Plug the measured σ² and ρ into the formula, and compare against the ACTUAL measured variance of the bagged ensemble's predictions (300 outer experiments, B=30 trees each, averaged per experiment):

Predicted: ρσ² + (1−ρ)σ²/B = 0.4446×1.4776 + (1−0.4446)×1.4776/30
= 0.6570 + 0.0289 = 0.6859
Real executed output — measured directly from 9,000 trained trees, not from the formula
Var_D[ bagged ensemble(x0) ] = 0.7200   (measured directly)
Formula prediction (using slightly different rng draw): 0.7191
Two completely independent computations — one from raw algebra using measured σ² and ρ, one from literally training thousands of trees and measuring the bagged ensemble's output variance directly — agree to within rounding/sampling error. The derivation is not just algebraically valid; it correctly predicts what actually happens when you run the experiment.
Var(single tree) / Var(bagged, B=30) = 1.6032 / 0.7200 = 2.23×

The One-Sentence Takeaway

Averaging B trees whose predictions are correlated at ρ cuts variance from σ² down to ρσ² + (1−ρ)σ²/B — and no matter how large B gets, it can never go below the floor ρσ². That floor is a permanent tax set entirely by how correlated the trees are, which is exactly why Random Forest doesn't stop at bootstrap sampling alone — it adds random feature subsampling specifically to push ρ down further, since more trees (bigger B) alone cannot touch that term.
