What to ask first

  • Regression, binary classification or multiclass?
  • How large is the dataset?
  • Numerical, categorical, sparse or mixed?
  • Linear or strongly nonlinear relationships?
  • Are interactions important?
  • Outliers, missing values, imbalance?
  • Latency, compute and interpretability constraints?

What “good model” actually means

A model is not good because it is sophisticated. It is good if it performs well on the right metric, generalizes to unseen data, satisfies operational constraints, and has an acceptable failure mode.

Interview answer: “I would establish a simple baseline first, then compare a few candidate model families under cross-validation using the metric that reflects the cost of errors.”
03 · Regression foundation

Linear Regression

Think: weighted sum of features → continuous prediction.

What is it?

Linear Regression assumes the target can be approximated by a linear combination of input features.

\[\hat y=\beta_0+\beta_1x_1+\cdots+\beta_px_p\]

What does it learn?

The coefficients \(\beta\) and intercept \(\beta_0\). Each coefficient says how the prediction changes when that feature changes by one unit, holding the other included features fixed.

Training: what actually happens?

1
Start with candidate coefficients.
2
Compute predictions \(\hat y_i\).
3
Measure squared errors.
4
Find coefficients that minimize total squared error.
\[\mathrm{MSE}=\frac1n\sum_{i=1}^{n}(y_i-\hat y_i)^2\]

Two ways to think about fitting

OLS / normal equation:
\[\hat\beta=(X^\top X)^{-1}X^\top y\]

A closed-form solution when the inverse is well-defined.

Gradient descent:

Start with weights → calculate loss → calculate gradient → move weights opposite the gradient → repeat.

\[\beta\leftarrow\beta-\eta\nabla_\beta L\]
🎯 WHEN TO CONSIDER
  • Relationship is approximately linear.
  • You need a strong, simple baseline.
  • Interpretability of coefficients matters.
  • Fast training/inference is valuable.
  • You want a model whose behavior is easy to reason about.
Why? Low complexity, transparent functional form and efficient optimization.
🔴 RECONSIDER WHEN
  • Strong nonlinearities or complex interactions dominate.
  • Outliers strongly distort the squared-error objective.
  • Severe multicollinearity makes coefficients unstable.
  • The data-generating relationship clearly has thresholds/branches.

Bias–variance and key behavior

ChangeEffectTypical consequence
More flexible features / polynomial degreeLower bias, higher varianceCan fit nonlinear patterns but may overfit
Ridge/Lasso regularization ↑Higher bias, lower varianceUsually reduces overfitting
Highly correlated featuresCoefficient instabilityPrediction can still be okay while coefficients become unreliable

Regularization: the practical extension

Ridge
\[\min_\beta\; \mathrm{SSE}+\lambda\sum_j\beta_j^2\]

Shrinks coefficients toward zero. Usually keeps all features.

Lasso
\[\min_\beta\; \mathrm{SSE}+\lambda\sum_j|\beta_j|\]

Can drive coefficients exactly to zero → embedded feature selection.

Hyperparameters / knobs

KnobIncrease / strongerDecrease / weaker
Ridge alpha \(\lambda\)More shrinkage → ↑ bias, ↓ varianceCloser to OLS
Lasso alpha \(\lambda\)More sparsity/shrinkageMore features retained
Prediction: new row → multiply each feature by its coefficient → add intercept → output number.
04 · Classification foundation

Logistic Regression

Think: linear score → sigmoid → probability → threshold → class.
Features \(x\)
→
Linear score \(z=w^\top x+b\)
→
Sigmoid \(p=\sigma(z)\)
\[\sigma(z)=\frac{1}{1+e^{-z}}\qquad 0

Why sigmoid?

It converts any real-valued score into a number between 0 and 1 that can be interpreted as a model probability under the usual setup.

Decision rule

With threshold \(t\):

\[\hat y=\mathbf{1}[p\ge t]\]

Changing \(t\) changes the precision/recall trade-off without retraining the model.

Training

1
Compute \(z_i=w^\top x_i+b\).
2
Convert score to probability \(p_i=\sigma(z_i)\).
3
Compare \(p_i\) with the observed class using log loss.
4
Optimize weights to minimize total loss, often with regularization.
\[\mathcal L=-\frac1n\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]\]

The useful interpretation

\[\log\frac{p}{1-p}=w^\top x+b\]

The linear model is linear in log-odds, not directly in probability.

🎯 WHEN TO CONSIDER
  • Binary classification with a roughly linear decision boundary.
  • You need a fast, interpretable baseline.
  • Feature effects / odds interpretation matter.
  • You need a probability score and want a simple model.
  • High-dimensional sparse features can be handled efficiently with suitable regularization.
🔴 RECONSIDER WHEN
  • The decision boundary is strongly nonlinear and feature engineering is insufficient.
  • Complex interactions are essential but not explicitly represented.
  • Tree ensembles clearly fit the tabular structure better.

Hyperparameters

ParameterMeaningTypical direction
CInverse regularization strength in sklearnC ↑ → weaker regularization → lower bias / higher variance
penaltyL1 / L2 / elastic-net depending solverL1 can create sparsity
class_weightReweights classesUseful for imbalance; changes training objective
thresholdPrediction operating pointHigher threshold → generally precision ↑, recall ↓

Multiclass: how does it happen?

One-vs-Rest (OvR)

Train one binary classifier per class: class A vs rest, B vs rest, etc. Pick the class with the strongest score/probability.

Multinomial / softmax
\[P(y=k|x)=\frac{e^{z_k}}{\sum_j e^{z_j}}\]

One model jointly produces class probabilities.

Remember: Logistic Regression does not become nonlinear just because there are many classes. The underlying score is still linear unless you add nonlinear features/transforms.
05 · Distance-based model

K-Nearest Neighbors (KNN)

Think: “similar points should have similar outcomes.”
New point
→
Compute distances to training points
→
Take K nearest

Training is unusual

Classic KNN has almost no parameter-fitting phase. It largely stores the training data.

Prediction is expensive

For a new point, calculate distances to candidate training points, select neighbors, then vote/average.

\[d(x,x')=\sqrt{\sum_j(x_j-x'_j)^2}\quad\text{(Euclidean example)}\]

Prediction

Classification

Majority vote among K neighbors. Weighted KNN can give closer neighbors more influence.

Regression

Average, or distance-weighted average, of neighbor target values.

🎯 WHEN TO CONSIDER
  • Dataset is small/moderate.
  • A meaningful distance/similarity measure exists.
  • Local structure matters more than a global functional form.
  • Decision boundary is nonlinear.
  • You want a useful nonparametric baseline.
🔴 RECONSIDER / AVOID WHEN
  • Dataset is huge → inference can be expensive.
  • Dimensionality is very high → curse of dimensionality.
  • Many irrelevant features destroy distance quality.
  • No meaningful distance metric exists.
  • Features have incompatible scales and cannot be sensibly normalized.

Bias–variance

KBiasVarianceBehavior
K smallLowerHigherVery local; sensitive to noise
K largeHigherLowerSmoother; may underfit

Hyperparameters

ParameterWhat it controlsKey effect
n_neighborsKK ↑ → bias ↑, variance ↓
weightsneighbor influencedistance weighting emphasizes nearby points
metric / pdistance geometryMust match the meaning of the features

Multiclass

No special OvR/OvO training is necessary. Look at the K neighbors and count each class; the highest vote wins. Probabilities can be estimated from class proportions among neighbors.

Scaling is critical: if age ranges 0–100 and income ranges 0–1,000,000, income can dominate Euclidean distance unless appropriately scaled.
06 · Rule-based nonlinear model

Decision Tree

Think: learn a sequence of if/else questions that makes the remaining groups as pure as possible.
Root ├── condition: Age < 35? │ ├── Yes → next best split │ └── No → next best split └── ... ↓ Leaf → prediction

Training: split-by-split

1
At the current node, generate candidate feature/threshold splits.
2
For each split, calculate how much impurity/loss decreases.
3
Choose the best split.
4
Repeat recursively on child nodes.
5
Stop according to depth, minimum samples, purity or other constraints.

Classification

\[Gini=1-\sum_kp_k^2\]

Entropy is another impurity measure. Lower impurity means a purer node.

Regression

Typical split criteria are based on squared error / variance reduction. A leaf prediction is usually the mean target in that leaf.

🎯 WHEN TO CONSIDER
  • Nonlinear relationships and feature interactions matter.
  • You want human-readable rules.
  • Scaling should not be necessary.
  • Threshold behavior is plausible.
  • You want a simple tree baseline before an ensemble.
🔴 RECONSIDER
  • A single tree is unstable/high variance.
  • You need very smooth predictions.
  • You need strong extrapolation outside the training range for regression.
  • Very deep trees become too complex to explain.

Hyperparameters

ParameterControlsIf increased
max_depthmaximum depthcomplexity ↑, bias ↓, variance ↑
min_samples_splitminimum rows needed to split↑ → simpler tree
min_samples_leafminimum rows in leaf↑ → smoother / less variance
max_leaf_nodesnumber of leaves↑ → more capacity
max_featuresfeatures considered at splitlower can decorrelate trees in ensembles

Multiclass

At a node, impurity is calculated over all classes. At a leaf, the class prediction is typically the majority class and class probabilities can be estimated from class proportions in that leaf.

Outliers, precisely: a split only asks "is x < threshold?" — so an input outlier just lands on whichever side it belongs to; its exact magnitude never enters the calculation. But a target outlier (regression) is different — if it lands alone or with few others in a leaf, the leaf's prediction (the mean of that leaf) gets pulled directly toward it. Feature-outlier-robust and target-outlier-immune are NOT the same claim — only the first is true for trees.
Core limitation: a deep decision tree can memorize training examples. That is why trees are the natural building block for ensembles such as Random Forest and boosting.
07 · Ensemble foundation

Bagging

Think: many models trained independently on different bootstrap samples → aggregate them.
Training data
→
Bootstrap sample 1 / 2 / 3 / …
→
Train models independently

Why does averaging reduce variance?

If each estimator has noise and their errors are not perfectly correlated, averaging cancels some of that noise.

\[\mathrm{Var}\left(\frac1B\sum_{b=1}^{B}f_b\right) =\rho\sigma^2+\frac{1-\rho}{B}\sigma^2\]

The key intuition: more models reduce the independent part of variance; lower correlation \(\rho\) makes the ensemble more effective.

🎯 WHEN TO CONSIDER
  • Base learners have high variance.
  • You want a more stable model than a single tree.
  • Parallel training is attractive.
  • You want variance reduction without sequential training.
🔴 RECONSIDER
  • The base learner is already strongly biased.
  • You need to sequentially correct systematic errors → boosting may be more appropriate.
Outliers, precisely: bagging doesn't remove any single base learner's sensitivity to an outlier — a tree that happens to bootstrap-sample the outlier still reacts to it exactly as a lone tree would (see Decision Tree above). What bagging changes is that only some of the B trees will have drawn that outlier in their bootstrap sample; averaging across all B dilutes its influence on the FINAL ensemble prediction, even though it wasn't "fixed" in any individual tree.
Bagging = parallel. Each learner is trained independently; aggregation is what reduces variance.
08 · Bagging + random features

Random Forest

Think: bagged decision trees + random feature subsets → diverse trees → aggregate.
Original data
→
Bootstrap rows
→
Random subset of features at each split
→
Many trees

Why random features?

Suppose one very strong feature dominates every tree. Without feature randomness, trees can become highly correlated. Random feature subsets force different trees to explore different structures, reducing correlation and making averaging more effective.

Classification: majority vote / aggregated class probabilities.
Regression: average tree predictions.
🎯 WHEN TO CONSIDER
  • Strong nonlinear tabular relationships.
  • You want a robust baseline with little feature scaling work.
  • Interactions matter.
  • You want lower variance than a single tree.
  • You value robustness and reasonable out-of-the-box behavior.
🔴 RECONSIDER
  • Maximum predictive performance on structured tabular data is the primary goal and boosting is available to tune.
  • Very high-dimensional sparse features can make tree ensembles inefficient.
  • You need a compact, easily explainable single model.

Hyperparameters

ParameterMeaningIncreasing it usually does
n_estimatorsnumber of treesMore stable; compute ↑; usually variance ↓ until saturation
max_depthtree complexity↑ → bias ↓, variance of individual trees ↑
max_featuresfeatures considered per splitLower → more diversity, potentially more bias
min_samples_leafminimum leaf size↑ → smoother, less overfit
bootstrapsample with replacementcore bagging behavior when True
max_samplesrows per bootstrap samplelower can increase diversity, but may increase bias

OOB intuition

With bootstrap sampling, some training rows are left out of a given tree. Those out-of-bag rows can act as an internal validation signal for that tree/forest without using a separate validation split for every tree.

Multiclass

Each tree can predict one of many classes. Aggregate the tree votes across all classes; the class with the highest vote wins. Probability estimates can be based on averaged tree probabilities.

Outliers, precisely: an input outlier is harmless for the same reason it's harmless in a single tree — splits use threshold order, not magnitude. A target outlier (regression) still pulls the mean of whichever leaf(s) it lands in, in whichever trees happened to bootstrap-sample it — but since it only influences a fraction of the B trees, and the forest averages all of them, its effect on the final prediction is diluted, not eliminated. More trees dilutes it further; it never disappears completely.
RF bias/variance headline: Random Forest is primarily a variance-reduction ensemble. More trees mainly stabilize the prediction; depth controls the capacity of the individual trees.
09 · Ensemble family

Boosting

Think: models are built sequentially; each new model focuses on what the current ensemble still gets wrong.
Initial model
→
Find remaining error / gradient
→
Fit next weak learner
→
Add small correction

Bagging vs Boosting

Bagging / RFBoosting
TrainingParallel / independentSequential
Main intuitionAverage away varianceCorrect residual/error step by step
CorrelationTry to decorrelate learnersLearners deliberately depend on previous learners
Typical riskCan retain biasCan overfit if complexity/iterations are uncontrolled
🎯 WHEN TO CONSIDER
  • Predictive performance on tabular data matters.
  • The relationship is nonlinear and interactions matter.
  • You can afford sequential training and tuning.
  • You need a powerful model with controlled incremental complexity.
🔴 RECONSIDER
  • Extremely strict training latency makes sequential learning impractical.
  • Data is extremely noisy and the model is allowed to become too complex.
  • You need a simple, transparent model as the final production choice.
Outliers, precisely — this is where boosting differs sharply from bagging/RF: an outlier isn't diluted by averaging here, because there's nothing to average against — every tree sees ALL the data, sequentially, not a random subset of it. A target outlier produces a large residual/gradient in round 1; the next tree is built specifically to correct that large error; the one after that keeps chasing whatever's still large. Left unchecked, boosting can spend many rounds fitting a handful of outliers ever more precisely — this is exactly why learning_rate, max_depth, and early stopping matter more here than in bagging.
Boosting mental model: don’t ask “how does one tree solve the problem?” Ask “what correction does the next tree need to make to the current ensemble?”
10 · Gradient boosting with trees

GBDT — Gradient Boosted Decision Trees

Important distinction: Classical gradient boosting is fundamentally based on the negative gradient / pseudo-residual. Do not automatically call it a second-order method. XGBoost explicitly introduces gradient + Hessian via a second-order Taylor approximation.

Core equation

\[F_m(x)=F_{m-1}(x)+\eta\,h_m(x)\]

\(F_{m-1}\) is the current ensemble, \(h_m\) is the new tree, and \(\eta\) is the learning rate.

Regression: easiest way to remember it

1
Start: choose an initial prediction that minimizes the loss. For squared-error regression, this is the target mean.
2
Compute residuals / negative gradients: for squared error, residual \(r_i=y_i-F(x_i)\).
3
Fit a small regression tree to those residuals.
4
Add a small part of that tree to the current model using \(\eta\).
5
Recompute the remaining errors and repeat.
\[r_{im}=-\left[\frac{\partial L(y_i,F(x_i))}{\partial F(x_i)}\right]_{F=F_{m-1}}\]

Why “gradient”?

The gradient tells us the direction in prediction space that would reduce the loss. The negative gradient points toward improvement.

Why trees?

The tree approximates a complicated function mapping feature space to the correction required at each observation.

Classification

Use a differentiable classification loss such as log loss. The tree is trained on the negative gradient of the loss with respect to the current prediction/score. The precise representation of the score depends on the implementation.

\[\text{For binary log loss, a key residual-like quantity is }y-p\]

Prediction after training

\[F_M(x)=F_0(x)+\eta h_1(x)+\eta h_2(x)+\cdots+\eta h_M(x)\]

One new row passes through every tree sequentially; all tree contributions are accumulated.

🎯 WHEN TO CONSIDER
  • Strong tabular predictive performance is desired.
  • You want nonlinearities + interactions without manual feature transformations.
  • Dataset size is manageable and a classic boosting implementation is sufficient.
  • You want a principled loss-driven model.
🔴 RECONSIDER
  • You need very fast training on massive data and a histogram implementation may be preferable.
  • You need extremely simple interpretability.
  • You have severe noise and let trees become too deep / iterations too high.

Hyperparameters

ParameterControlsTypical effect
n_estimatorsnumber of boosting stages↑ capacity; can overfit
learning_ratesize of each correction↓ usually requires more trees; often improves control
max_depthtree complexity↑ captures higher-order interactions; variance/overfit risk ↑
min_samples_leafleaf granularity↑ regularizes
subsamplerow fraction per stage<1 adds stochasticity; can reduce variance
Classic GBDT memory loop: current model → negative gradient → small tree → add correction → repeat.
11 · Regularized second-order boosting

XGBoost

Think: GBDT + second-order loss information + explicit regularization + efficient tree construction.

What changes?

XGBoost uses a second-order Taylor approximation of the objective around the current predictions. For each training row it uses both the gradient \(g_i\) and Hessian \(h_i\).

\[\mathcal L^{(t)}\approx\sum_i\left[g_i f_t(x_i)+\frac12h_i f_t(x_i)^2\right]+\Omega(f_t)\]
Gradient \(g_i\)

First derivative: direction/slope of loss with respect to current prediction.

Hessian \(h_i\)

Second derivative: local curvature; tells how quickly that slope changes.

Leaf weight: the key interview formula

\[w^*=-\frac{G}{H+\lambda}\]

where \(G=\sum_i g_i\) and \(H=\sum_i h_i\) for the rows in that leaf.

Why this makes sense

If the summed gradient says “move predictions downward,” the negative sign moves the leaf in that direction. The Hessian + regularization controls how aggressive that movement should be.

Split gain intuition

\[\mathrm{Gain}\approx\frac12\left(\frac{G_L^2}{H_L+\lambda}+\frac{G_R^2}{H_R+\lambda}-\frac{G^2}{H+\lambda}\right)-\gamma\]

A split is attractive when separating the data into left/right children produces substantially better optimized leaf objectives than keeping them together, after regularization.

🎯 WHEN TO CONSIDER
  • High-quality tabular prediction is important.
  • You want strong regularization controls.
  • Feature interactions and nonlinearities matter.
  • You need a mature, highly tunable gradient-boosting implementation.
  • You want explicit control over tree depth, row/column subsampling and L1/L2 regularization.
🔴 RECONSIDER
  • The problem is tiny and a simpler model already meets the goal.
  • Strict interpretability dominates performance.
  • Hyperparameter complexity is undesirable for a simple baseline.

Important hyperparameters

Multiclass

Multiclass objectives can jointly model multiple classes through class-specific scores/probabilities. Conceptually, the model learns scores for classes and converts them to probabilities (e.g. softmax for multiclass logistic objectives).

Do not mix these up: GBDT’s core idea is negative-gradient correction. XGBoost’s key mathematical distinction is second-order Taylor information: gradient + Hessian, plus regularization and engineering improvements.
12 · Histogram + leaf-wise boosting

LightGBM

Think: gradient boosting optimized for large tabular data using histogram bins and leaf-wise/best-first tree growth.

Histogram-based splitting

Continuous feature values are bucketed into discrete bins. Instead of checking every unique threshold, the algorithm works with bin statistics, reducing computation and memory pressure.

Leaf-wise growth

Instead of growing every level uniformly, LightGBM chooses the leaf whose split is expected to give the largest gain and splits that leaf next.

Level-wise (rough idea) root / \ split split / \ / \ Leaf-wise / best-first root / \ leaf leaf* ↓ split the leaf with greatest gain
Trade-off: leaf-wise growth can reach lower training loss quickly, but with insufficient constraints it can overfit. num_leaves, max_depth and minimum leaf constraints become important.

GOSS and EFB — know the intuition

GOSS

Gradient-based One-Side Sampling prioritizes observations with larger gradients while retaining a representative sample of smaller-gradient observations. Intuition: focus computation on rows where the model is still making substantial mistakes.

EFB

Exclusive Feature Bundling groups features that are rarely nonzero together, reducing the effective number of features in sparse settings.

🎯 WHEN TO CONSIDER
  • Large tabular datasets.
  • Training efficiency matters.
  • Complex nonlinear interactions exist.
  • You want histogram-based gradient boosting with aggressive tree growth.
  • Sparse/high-dimensional structures can benefit from efficient handling.
🔴 RECONSIDER
  • Dataset is tiny and a simple model is sufficient.
  • Leaf-wise growth is poorly constrained and overfitting becomes severe.
  • You need a very transparent model rather than a high-capacity ensemble.

Hyperparameters

ParameterMeaningKey behavior

learning_ratestep size↓ smaller corrections; usually more trees

Multiclass and missing values

Multiclass boosting uses class-aware objectives and produces scores/probabilities across classes. LightGBM also has native handling for missing values in its tree-building framework; the exact behavior is implementation-specific, so do not equate “native missing handling” with “missingness never matters.”

LightGBM memory: histogram bins reduce split-search cost; leaf-wise growth aggressively attacks the best remaining leaf; this is powerful but must be constrained.
13 · Probabilistic model

Naive Bayes

Think: Bayes theorem + conditional independence assumption → compare posterior probabilities for classes.
\[P(y|x_1,\ldots,x_d)\propto P(y)\prod_{j=1}^{d}P(x_j|y)\]
Prior

\(P(y)\): how common the class is before seeing features.

Likelihood

\(P(x_j|y)\): how compatible each feature is with that class.

Prediction

1
Estimate class priors from training data.
2
Estimate feature likelihoods conditional on each class.
3
For a new row, multiply prior × feature likelihoods (or add log probabilities).
4
Choose the class with the largest posterior score.
Why “naive”? It assumes features are conditionally independent given the class. This assumption is often false, yet the classifier can still perform surprisingly well.

Variants

VariantTypical dataCore assumption
Gaussian NBcontinuous featuresfeature distribution per class modeled as Gaussian
Multinomial NBcounts / textfeature counts modeled conditionally on class
Bernoulli NBbinary featuresfeature presence/absence
🎯 WHEN TO CONSIDER
  • Fast baseline for classification.
  • High-dimensional sparse text/count features.
  • Small datasets where a simple probabilistic assumption is attractive.
  • Training and inference speed are important.
🔴 RECONSIDER
  • Strong feature dependencies make the independence assumption damaging.
  • You need rich nonlinear interactions.
  • Probability calibration is critical without post-calibration.
Numerical stability: implementations often work in log space: \(\log P(y)+\sum_j\log P(x_j|y)\), avoiding underflow from multiplying many tiny probabilities.
14 · Practical reasoning

How to choose the algorithm

The decision framework

1
Define target: regression / binary / multiclass.
2
Understand data: rows, features, sparsity, categorical/numerical, missingness, imbalance, outliers.
3
Understand structure: linear? nonlinear? local similarity? interactions?
4
Start with baseline: simple model that gives a trustworthy reference.
5
Choose 2–3 candidates based on the problem, not popularity.
6
Validate properly using the business-relevant metric.
7
Tune + inspect failure modes: overfit, calibration, imbalance, leakage, latency.
8
Choose final model by performance + operational constraints + maintainability.
Problem signalModels to think about firstWhy
Simple linear relationship + interpretabilityLinear / Logistic RegressionLow complexity, fast, explainable
Small data + local similarityKNNNonparametric local behavior
Nonlinear + simple rules neededDecision TreeReadable thresholds/interactions
Nonlinear tabular + robust baselineRandom ForestVariance reduction + low preprocessing burden
Strong tabular performanceGBDT / XGBoost / LightGBMSequential error correction + interactions

No universal winner: “XGBoost is best” is not a model-selection argument. A good answer explains why the model fits the data, metric and constraints.

Naive BayesCan be sensitiveCan be sensitiveOutliers can distort estimated feature distributions/likelihoods depending on variant.
Never say “trees are unaffected by outliers.” Better: tree splits are generally insensitive to feature scale and extreme feature magnitude — but target outliers still change leaf predictions. And the ensemble strategy matters: bagging/RF dilutes an outlier's effect through averaging across a random subset of trees; boosting doesn't dilute it at all — it sequentially targets whatever residual is currently largest, which is exactly why boosting needs learning_rate/depth/early-stopping discipline that bagging doesn't need nearly as much.
16 · Classification reliability

Class imbalance

If 99% are negative and 1% positive, a 99% accurate model can be completely useless for the positive class.

Why accuracy fails

Predicting the majority class every time can achieve high accuracy while having zero recall for the minority class.

First things to inspect

Confusion matrix, positive precision/recall, PR curve, class distribution and the actual cost of FP vs FN.

Solutions

ApproachWhat changesProsRisk / caveat
Class weightsPenalize minority mistakes moreSimple; no synthetic dataCan shift decision boundary; may hurt calibration
OversamplingIncrease minority training examplesMore minority signalCan overfit duplicated points
UndersamplingReduce majority examplesFaster; balances dataThrows away information
SMOTESynthesize minority points between neighborsCan reduce duplicationCan create unrealistic points; must avoid leakage
Threshold tuningChange classification operating pointNo retrainingDoes not create new model information
Critical: SMOTE/oversampling must be applied inside the training portion of each CV fold. Applying it before cross-validation lets information from validation folds influence synthetic training examples.
Imbalance is not solved by one metric. Decide whether false positives or false negatives are more costly, then select the metric and threshold accordingly.

22 · Evaluation

Classification metrics

Start with the confusion matrix

Actual PositiveActual Negative
Predicted PositiveTPFP
Predicted NegativeFNTN
Precision
\[\frac{TP}{TP+FP}\]

Of predicted positives, how many were truly positive?

Recall / TPR / Sensitivity
\[\frac{TP}{TP+FN}\]

Of actual positives, how many did we catch?

Specificity / TNR
\[\frac{TN}{TN+FP}\]

Of actual negatives, how many did we correctly reject?

F1
\[F1=\frac{2PR}{P+R}\]

Harmonic mean; useful when both precision and recall matter.

F-beta

\[F_\beta=(1+\beta^2)\frac{PR}{\beta^2P+R}\]

\(\beta>1\) emphasizes recall; \(\beta<1\) emphasizes precision.

Accuracy

\[\frac{TP+TN}{TP+TN+FP+FN}\]

Useful when classes are reasonably balanced and FP/FN have comparable importance. Dangerous as a primary metric under severe imbalance.

Macro vs Micro vs Weighted F1

AverageHowMemory
Macro F1Compute F1 per class → simple averageEvery class gets equal weight
Micro F1Aggregate TP/FP/FN across classes → then F1Each individual prediction contributes equally
Weighted F1F1 per class weighted by class supportLarge classes influence the score more

ROC-AUC

\[TPR=\frac{TP}{TP+FN},\qquad FPR=\frac{FP}{FP+TN}\]

ROC plots TPR against FPR across thresholds. AUC summarizes ranking quality across thresholds.

Imbalance caveat: with a huge negative class, even a small FPR can correspond to many false positives. ROC-AUC may therefore look impressive while positive-class precision is poor.

PR-AUC

Precision–Recall curves focus directly on the positive class. PR-AUC is often more informative when the positive class is rare and finding useful positives is the main objective.

25 · Interview traps

Things I must not get wrong

Why does scaling matter for KNN but not trees?

KNN uses distances, so feature magnitude directly changes neighborhood geometry. Trees compare feature values against thresholds; monotonic rescaling changes the numeric threshold but not the ordering, so predictions are generally unchanged.

Why does Random Forest reduce variance?

It averages many diverse trees. Averaging reduces the independent component of prediction noise, especially when tree errors are not perfectly correlated.

Why can boosting overfit?

Sequential learners keep adding corrections. With too many rounds, overly deep trees, or too little regularization, the ensemble can start fitting noise and idiosyncrasies of the training set.

Why does increasing K in KNN usually increase bias?

A larger neighborhood averages over a broader region, smoothing local structure. That reduces variance but can wash out genuine local boundaries.

Why can ROC-AUC look good under severe imbalance?

FPR uses the huge negative denominator. A small FPR can still mean many false positives, so positive-class precision can remain poor.

Macro vs micro vs weighted F1?

Macro gives every class equal weight. Micro pools decisions across classes. Weighted averages per-class F1 using class support, so majority classes influence the result more.

Why must SMOTE be inside CV?

If synthetic examples are created before splitting folds, information derived from future validation rows can influence training data. That leaks information and inflates validation performance.

GBDT vs XGBoost?

GBDT is the general gradient-boosting framework. XGBoost is a highly engineered, regularized implementation that uses second-order Taylor information (gradient + Hessian) in its objective optimization.

What is the key LightGBM idea?

Histogram-based split search plus leaf-wise/best-first growth. It can be very efficient and powerful, but leaf-wise growth requires careful complexity constraints.

What is the difference between split criterion and leaf value?

The split criterion decides where to partition data. The leaf value decides what prediction the resulting region contributes. In XGBoost, for example, the optimized leaf weight uses \(-G/(H+\lambda)\).

Why is Naive Bayes “naive”?

It assumes features are conditionally independent given the class. That assumption simplifies the joint likelihood into a product of individual likelihoods.

Does changing the classification threshold retrain the model?

No. The model's scores/probabilities stay the same; only the rule that converts them into class labels changes.

26 · 30-minute revision

The rapid pass

Linear

Weighted sum. Low complexity. Great baseline. Regularize with Ridge/Lasso.

Logistic

Linear score → sigmoid → probability. Threshold controls operating point.

KNN

Distance → K neighbors → vote/average. Scaling critical. K↑ bias↑ variance↓.

Tree

Best split → recurse → leaf. Nonlinear. Deep tree = low bias/high variance.

RF

Bootstrap trees + random features + aggregation. Mainly variance reduction.

Bagging

Independent learners. Parallel. Average/vote to stabilize.

GBDT

Current model → negative gradient → small tree → add correction → repeat.

XGBoost

Gradient + Hessian + regularization. Leaf \(=-G/(H+\lambda)\).

LightGBM

Histogram bins + leaf-wise growth. Fast and powerful; constrain leaves.

Naive Bayes

Prior × likelihoods under conditional independence. Fast, especially useful for sparse text.

Outliers

Distance and squared-loss models care more. Trees are feature-outlier robust but target outliers can still matter.

Imbalance

Accuracy can lie. Think PR-AUC, precision, recall, class weights and threshold tuning.

27 · Final mental checklist

If you remember only 25 things

  1. Always define the target and business cost before choosing a model.
  2. Linear Regression learns a weighted linear prediction of a continuous target.
  3. Logistic Regression learns a linear score and maps it to probability with sigmoid.
  4. Logistic classification is threshold-dependent.
  5. KNN is lazy: most work happens at prediction time.
  6. KNN needs a meaningful distance and usually careful scaling.
  7. K↑ in KNN → bias↑, variance↓.
  8. Decision Trees learn recursive threshold rules.
  9. Deep trees → lower bias but higher variance.
  10. Bagging trains learners independently and aggregates them.
  11. Random Forest adds random feature selection to decorrelate trees.
  12. Random Forest mainly attacks variance.
  13. Boosting trains sequentially and adds corrections.
  14. Classic GBDT fits trees to negative gradients / pseudo-residuals.
  15. GBDT prediction is the sum of incremental tree contributions.
  16. XGBoost uses gradient + Hessian through a second-order approximation.
  17. XGBoost leaf weight is based on \(-G/(H+\lambda)\) in the regularized formulation.
  18. LightGBM uses histogram-based split search and leaf-wise growth.
  19. Leaf-wise growth can overfit if the tree is not constrained.
  20. Naive Bayes assumes conditional feature independence given the class.
  21. Tree models generally do not need feature scaling.
  22. Input outliers and target outliers are different problems.
  23. Accuracy is dangerous when classes are highly imbalanced.
  24. PR-AUC is often more useful than ROC-AUC for rare positive classes.
  25. Never tune or preprocess using information from the untouched test set.
Final interview mindset: do not answer “I would use XGBoost” immediately. First say what you know about the target, data shape, nonlinearities, imbalance, metric, latency and interpretability. Then choose a few candidate families and explain the trade-off.
