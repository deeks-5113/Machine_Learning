Class summary
Where we left off

Recap: what we already know — predicting a number

ŷ = w₁x₁ + w₂x₂ + … + w₀

This is the prediction itself — ŷ ("y-hat"). The target y was always a real number: price, temperature, salary — anywhere on the number line, and ŷ tried to land exactly on it. "Wrong" meant a numeric distance, measured with Mean Squared Error.

Today: the target is now a category, not a number

Example: will a student pass an exam, based on hours studied? y ∈ {0, 1} — fail or pass, nothing in between. This is called binary classification.

Plotted, the data only ever forms two flat bands — a cloud of 0s low down, a cloud of 1s up top. There's no numeric "value" to get close to anymore — only a label to get right or wrong.

Why fitting a line is bad here

We want an output between 0 and 1 (something we can read as "how likely is pass"). A plain line doesn't give us that.

ŷ = −0.15 + 0.09h
hours (h)ŷvalid?
0−0.15✗ negative — meaningless
131.02✗ above 1 — meaningless
A straight line's output lives in (−∞, +∞). Our target only ever lives in {0, 1}. Wrong shape of function — before we even ask if it fits the pattern well.
The geometric picture

Regression vs. Classification — side by side

Regression — 2D example

Price of a car vs. its age. The best line is the one that passes through (close to) as many points as possible — minimizing vertical distance.

Line runs THROUGH the cloud of points

Classification — 2D example

Two classes of points. The best line separates class 1 from class 0 — it doesn't try to pass through anyone.

Line SEPARATES the two clouds — separator, not a fit

In 3D, the separator becomes a plane

With two features, a line separates. With three features, a plane separates. With more features, it's a hyperplane — same idea, just more dimensions. The equation is always the same shape: z = w₁x₁ + w₂x₂ + …

A separating plane between two clusters of points in 3D feature space

The separating line is best for us — but how do we get it?

In regression, "good" meant small distance to every point. In classification, "good" means every class-1 point ends up on one side, every class-0 point on the other. That needs a completely different objective to optimize.

The idea: maximize yᵢ · wᵀxᵢ

Encode labels as y ∈ {+1, −1} instead of {0,1}. Define the raw score z = wᵀx. Multiply the true label by the score — this single quantity tells us, in one number, whether a point is correctly classified.

Wait — wᵀx=0 AND x₁+x₂=3? Aren't those different equations?

They look different, but they're the exact same line — one written generally, one written with our specific numbers plugged in. Here's exactly why.

the trick To fit an intercept (w₀) inside a clean dot product, we quietly attach an extra "feature" that's always 1. So the weight vector and feature vector actually look like this:
w = [w₀, w₁, w₂] = [−3, 1, 1]     x = [1, x₁, x₂]
multiply it out wᵀx = w₀·1 + w₁·x₁ + w₂·x₂ = −3(1) + 1(x₁) + 1(x₂) = −3 + x₁ + x₂
set it to zero wᵀx = 0  ⟺  −3+x₁+x₂ = 0  ⟺  x₁+x₂ = 3
"wᵀx=0" is the general, compact way to write the boundary — it works no matter how many features or what weights you have. "x₁+x₂=3" is that exact same equation after we've plugged in our specific weights (w₀=−3, w₁=1, w₂=1) and simplified. Same line, two ways of writing it — not two different things.

What is a "plane," exactly?

An equation like w₀+w₁x₁+w₂x₂+…=0 always carves up the feature space into two halves. What that boundary looks like just depends on how many features you have:

featuresthe equation w₀+w₁x₁+…=0 draws a…picture
2 (x₁, x₂)straight line in a flat 2D pagewhat we've been drawing
3 (x₁, x₂, x₃)a flat plane slicing through 3D spacea flat sheet, like a tilted piece of paper floating in a room
4 or morea "hyperplane"same idea, just too many dimensions to draw
It's always the same object playing the same role — split everything into "positive side" and "negative side." Only the name and the picture change as dimensions increase.

How do we check which side a point is on? (the actual procedure)

There's only one step: substitute the point's coordinates into w₀+w₁x₁+w₂x₂+… and compute the number.

resultmeaning
exactly 0the point lies exactly ON the line/plane
positivethe point is on the positive side
negativethe point is on the negative side

Example 1 — a line in 2D

w₀=−3, w₁=1, w₂=1  →  z = −3+x₁+x₂

pointsubstitutezresult
P=(1,2)−3+1+20exactly ON the line
Q=(4,4)−3+4+4+5positive side
R=(0,0)−3+0+0−3negative side
Check P: x₁+x₂ = 1+2 = 3 — yes, that matches x₁+x₂=3 exactly. P really does sit on the line.

Example 2 — a plane in 3D

w₀=−6, w₁=1, w₂=1, w₃=1  →  z = −6+x₁+x₂+x₃

pointsubstitutezresult
P=(2,2,2)−6+2+2+20exactly ON the plane
Q=(3,3,3)−6+3+3+3+3positive side
R=(1,1,1)−6+1+1+1−3negative side
Same exact procedure as Example 1 — just one more number to add. Nothing about the method changes as dimensions grow.

Seeing Example 1 on a graph

The line wᵀx=0 (x₁+x₂=3) splits the plane into two halves. Every point on the coral side gives a positive wᵀx; every point on the blue side gives a negative wᵀx. The farther a point sits from the line, the larger |wᵀx| gets.

This is the whole picture behind the four cases below: wᵀx's sign tells you which side of the line a point is on — it says nothing yet about whether that's the "correct" side. To know if the model got it right, we still need to compare this sign against the point's actual label, yᵢ. That comparison is exactly yᵢ·wᵀxᵢ.

The four conditions

caseyᵢwᵀxᵢyᵢ·wᵀxᵢmeaning
1+1> 0positive✓ correctly classified
2+1< 0negative✗ misclassified
3−1> 0negative✗ misclassified
4−1< 0positive✓ correctly classified
The pattern: yᵢ·wᵀxᵢ > 0 exactly when the prediction agrees with the truth — regardless of which class. So the fitting goal becomes simple to state: find w that makes yᵢ·wᵀxᵢ as large (as positive) as possible, for every point.

Where this breaks: outliers

Try to directly maximize the raw sum Σ yᵢ·wᵀxᵢ, with no bound on it, and two problems show up immediately.

problem 1 This objective is unbounded. For any already-correctly-classified point, you can always make yᵢ·wᵀxᵢ even bigger just by scaling ‖w‖ up — with no limit. The "best" w keeps wanting to grow forever, not settle anywhere.
problem 2 A single outlier — a point sitting unusually far out in feature space — produces a huge |wᵀxᵢ|. If it's on the wrong side, it contributes a massive negative number to the sum; if it's on the right side, a massive positive one. Either way, one extreme point can dominate and distort the entire fit, dragging the line around to accommodate it at the expense of every other point.
Raw, unbounded wᵀx gives a single extreme point unlimited leverage over the line. That's the failure case.

The fix: pass z through the sigmoid function

Instead of working with the raw, unbounded score z = wᵀx, squash it through σ(z) = 1/(1+e⁻ᶻ) first.

Because σ is bounded between 0 and 1, no matter how extreme wᵀxᵢ gets for an outlier, its contribution saturates — it caps out near 0 or near 1 and can't grow any further. The outlier's leverage over the fit is eradicated, or at the very least reduced to a big extent, compared to working with the raw unbounded score.
Making sense of it

Output: Regression vs. Logistic Regression

Regression's output

ŷ = w₁x₁ + … + w₀

ŷ IS the prediction — a direct estimate of y itself, same units, same scale, unbounded (−∞ to +∞).

Logistic Regression's output

z = w₁x₁+…+w₀  →  ŷ = σ(z)

z is just an intermediate score. ŷ = σ(z) is the actual prediction — a probability, bounded strictly between 0 and 1.

Why "regression," why "logistic"

part of the namewhy
"Regression"We're still fitting a line (or plane) — z = w₁x₁+…+w₀ is exactly the same linear combination of weights and features as before. Geometrically, it's still a line/plane doing the work.
"Logistic"Because we then pass that line's score through the logistic (sigmoid) function to turn it into a probability between 0 and 1, instead of leaving it as a raw, unbounded number.

In sklearn: predict() vs. predict_proba()

methodreturns
model.predict(X)0 or 1 — the hard class label, using the default threshold of 0.5 on the probability
model.predict_proba(X)the exact probability values themselves (e.g. 0.13, 0.87) — no thresholding applied
The 0.5 threshold is a default, not a law — you can use a custom threshold. We'll discuss exactly when and why you'd want to change it in a later class.

A question to sit with until next class

We now have: probability p lives strictly between 0 and 1. But our line's raw score z lives between −∞ and +∞. That's a mismatch — so what quantity, related to p, would actually live on the full −∞ to +∞ range, matching what a line naturally produces?

The answer involves something called odds, and then log-odds. Quick preview only, no derivation yet:

quantityrange
probability, p[0, 1]
odds = p/(1−p)[0, +∞)
log(odds)(−∞, +∞) — matches z!
