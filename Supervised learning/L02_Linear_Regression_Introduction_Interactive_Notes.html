Starting from scratch

What is regression?

Regression is a supervised learning technique used to predict a continuous numeric value, by learning the relationship between input variables and a known output.

Definition

Given some input(s) X, learn a function that maps to a real-valued output y — a number that can fall anywhere on the number line, not one of a fixed set of buckets.

input (hours) → model → output (score)

Easy example · predicting exam score

Narrowing it down

What is linear regression?

Linear regression is a regression method that models the relationship between input and output as a straight line — assuming the output changes at a constant rate as the input changes.

The equation

y = mx + c
y = predicted output  ·  x = input  ·  m = slope  ·  c = intercept
hours studied vs exam score — points hug a straight line
Two flavours

Univariate vs multivariate

Same idea, more dimensions — whether it's a line or a plane, linear regression always fits the flattest, straightest shape that best matches the data.

01 · Univariate — one input variable

Predicts output from a single feature.

y = mx + c

Only one input drives the prediction. The model fits a single straight line through the data points — easy to plot on a 2D graph.

example: predicting exam score using only "hours studied".

02 · Multivariate — two or more input variables

Predicts output from several features together.

y = m1x1 + m2x2 + ... + mnxn + c

Multiple inputs combine, each with its own weight, to drive the prediction. The model now fits a plane (or hyperplane) through the data.

example: predicting house price using "size", "bedrooms", and "location score" together.

a best-fit plane across dimensions — the multivariate picture

Fixing a flaw

The cost function (MSE)

We said: add up all the ei, and the smallest total wins. There's a catch — and fixing it gives us the actual cost function linear regression optimizes.

The problem with summing raw errors

Positive and negative errors can cancel out, hiding a genuinely bad fit:

Pointy (actual)ŷ (predicted)ei
11,000,1001,000,000+100
2999,9001,000,000−100
31,010,0001,000,000+10,000
4990,0001,000,000−10,000
Σ ei (raw sum)0
A total error of 0 here is misleading — this line is missing by ±10,000 at two points, not fitting perfectly.

Make every error positive before adding

If signs are the problem, remove the sign. Two natural ways to do that:

Option A
Absolute value
|ei| = |yi − ŷi|
Just drop the negative sign, keep the size. −1 and +1 both become 1.
Option B
Squaring
ei2 = (yi − ŷi)2
Multiply the error by itself. Any negative times a negative is positive, so the sign always disappears.
PatternErrorsΣ|ei|Σei2
A · spread out2, 2, 2, 2816
B · one big miss8, 0, 0, 0864
Both patterns have the same total |ei| = 8. But pattern B's one large miss gives it a squared total of 64 — four times higher than pattern A. Squaring makes big mistakes stand out, which is exactly the behaviour we want from a cost function.

Minimize the sum of squared errors

minimize nΣi=1 (yi − ŷi)2

For every point, take the actual value minus the predicted value, square the result, then add up all n of these squared errors.

This quantity is called the sum of squared errors (SSE) — also written as RSS, residual sum of squares.
MSE = 1
n nΣi=1 (yi − ŷi)2

n = the number of data points. We divide the SSE by n to get the average squared error per point.

★ this is the quantity linear regression minimizes — the mean squared error, our cost function J(w1, w0)

How the model actually learns

Gradient descent — the intuition

We now have a cost function — MSE. The next question is simple to state and hard to brute-force: which weights minimize it? Gradient descent is one way to search for the answer.

MSE is really a function of w1 and w0

Substitute ŷi = w1xi + w0 back into the MSE formula. This makes it explicit: the cost depends entirely on which weights we pick.

MSE(w1, w0) = 1
n nΣi=1 (yi − (w1xi + w0))2

Every xi and yi is fixed — it's the data we already have. w1 and w0 are the only things left to choose.

★ our job: search over every possible (w1, w0) pair and find the one that makes this smallest
each step recomputes the gradient and moves a little further downhill — notice the steps get naturally smaller as the curve flattens near the bottom

Where do we begin?

There's no special starting weight required — that's the point of an iterative search. The most common choice is simply:

w1 = 0    w0 = 0

(some implementations use small random values instead — either way, it's just a place on the bowl to start walking from. A bad starting guess still reaches the same minimum, it just takes more steps.)

Making it self-readable

Gradient descent — step by step

Seven small steps, in order: differentiate the cost function, see what the slope tells us, understand why we subtract it, pick a step size, write the update rule, then run it by hand on real numbers.

Step 1 — where we're starting from

Same cost function as before, written with a shorthand for the error at each point — it makes the differentiation in Step 2 much easier to follow.

MSE(w1,w0) = 1
n nΣi=1 ui2     where  ui = yi − (w1xi + w0)

ui is just the error at point i, written out in full instead of hidden behind "ŷi" — that's the only change, and it makes the chain rule below explicit.

Step 2 — differentiate, term by term (chain rule)

MSE is a function of two variables, so we take the partial derivative with respect to w1 and w0 separately. Each time, the same chain rule applies: differentiate the "outer" square, then multiply by the derivative of the "inner" bracket.

2.1
w.r.t. w1 — outer derivative first:
d/du (u2) = 2u   →   d/dw1 (ui2) = 2ui · (dui/dw1)
Now the inner derivative: ui = yi − w1xi − w0. Only the −w1xi term depends on w1, and its derivative is −xi.
dui/dw1 = −xi   →   d/dw1(ui2) = 2ui·(−xi) = −2xiui
Sum this over all n points and divide by n (the 1/n out front never changes):
∂MSE/∂w1 = − 2
n nΣi=1 xiui = − 2
n nΣi=1 xi(yi − ŷi)
2.2
w.r.t. w0 — identical process, different inner derivative:
dui/dw0 = −1   →   d/dw0(ui2) = 2ui·(−1) = −2ui
∂MSE/∂w0 = − 2
n nΣi=1 ui = − 2
n nΣi=1 (yi − ŷi)
Both gradients come from the exact same chain rule — only the "inner derivative" differs: −xi for w1 (because w1 multiplies x), and −1 for w0 (because w0 stands alone).

Step 3 — what the gradient actually tells us (verified)

The gradient is the slope of the cost curve at whatever weight we're currently standing on. It always points in the direction that makes the cost increase fastest — so gradient descent always steps opposite it. Two positions on the bowl, checked against the actual slope:

case A — left of the minimum: tangent tilts down-right → slope is negative → w1 should increase
case B — right of the minimum: tangent tilts up-right → slope is positive → w1 should decrease
Both cases move opposite their own slope, and both end up walking toward the minimum from wherever they started — that's the entire mechanism of gradient descent in one picture.

Step 4 — why the minus sign in the update rule?

The rule is wnew = wold − α · (gradient). Here's the plain-English reason for that minus sign, using the two cases from Step 3:

Case A — gradient is negative
Say the gradient works out to −640. Subtracting a negative number is the same as adding it:
wnew = wold − α×(−640) = wold + (positive number)
w goes up — exactly the "move right" direction Step 3 called for.
Case B — gradient is positive
Say the gradient works out to +640. Subtracting a positive number makes w smaller:
wnew = wold − α×(+640) = wold − (positive number)
w goes down — exactly the "move left" direction Step 3 called for.
One rule, both directions handled automatically. Subtracting the gradient always pushes w toward the minimum, no matter which side we started on — there's never a need for separate "if left, add; if right, subtract" logic. That's the whole reason the minus sign is there.

Step 5 — the learning rate, α

α (alpha) is a small positive number we choose before training — it controls how big each step is. Get it wrong in either direction and gradient descent struggles, even though the direction (Steps 3–4) is correct:

α too small — technically converges, but could take thousands of iterations
α just right — reaches the minimum in a handful of sensible steps
α too large — jumps clean over the minimum, can even diverge
There's no universal "correct" α — it depends on the data and the shape of the cost surface. In practice it's tuned by trying a few values (0.1, 0.01, 0.001…) and watching whether the cost drops smoothly, iteration after iteration.

Step 6 — putting it together: the update rule

w ← w − α · (∂J/∂w)
w1 ← w1 − α · (∂MSE/∂w1)
w0 ← w0 − α · (∂MSE/∂w0)

This gets repeated over and over — recompute the gradient at the new weights, take another small step — until the weights stop changing much. That's convergence: we've reached (or landed very close to) the minimum.

Optional — going deeper

Deriving w = (XTX)−1XTy

Gradient descent walks toward the minimum step by step. But for linear regression specifically, there's a shortcut: solve for the minimum directly, in one shot, using calculus and matrix algebra. Derived here — not assumed.

A minimum is where the slope is zero

Forget weights and datasets for a second. For any smooth, bowl-shaped function f(x), the lowest point is exactly where its slope — its derivative — equals zero.

f(x) = (x − 3)2
f'(x) = 2(x − 3)
set f'(x) = 0 → 2(x − 3) = 0 → x = 3

That's it — the entire principle. We differentiate, set it to zero, and solve. Everything below just applies this same idea to J(w), a bowl-shaped function of the weight vector instead of a single number.

Package the data into X, w, and y

Let n = number of data points. Define:

X — the input matrix (n rows, one per data point). Each row is [1, xi] — the 1 is a fixed placeholder that lets w0 act as the intercept.
X = 1  1
1  2
1  3  (example: first 3 students, x = 1, 2, 3)
w — the weight vector (what we're solving for)
w = w0
w1
y — the actual outputs
y = 42
50
55
ŷ = Xw

Multiplying X by w produces every prediction at once — row 1 of X times w gives ŷ1, row 2 gives ŷ2, and so on. This single matrix equation replaces n separate equations.

Sum of squared errors becomes a dot product

Let e = y − Xw be the vector of every error. We need Σei2 — and a vector dotted with itself gives exactly that:

eTe = [e1 e2 ... en] · [e1 e2 ... en]T = e12 + e22 + ... + en2

So the cost function — call it J(w) — is:

J(w) = eTe = (y − Xw)T(y − Xw)

This single expression is exactly SSE, written using matrices instead of a summation sign.

Multiply out the brackets like ordinary algebra

4.1
Distribute, just like (a − b)(a − b):
J(w) = yTy − yTXw − (Xw)Ty + (Xw)T(Xw)
4.2
Use (AB)T = BTAT to simplify (Xw)T:
(Xw)T = wTXT
So the third term becomes wTXTy, and the fourth becomes wTXTXw.
J(w) = yTy − yTXw − wTXTy + wTXTXw
4.3
The two middle terms are actually the same number.
yTXw is a 1×1 matrix — a plain scalar. A scalar always equals its own transpose: (yTXw)T = wTXTy. So yTXw = wTXTy — two identical terms just combine.
J(w) = yTy − 2wTXTy + wTXTXw
This is fully expanded now — three clean terms: a constant, a linear term in w, and a quadratic term in w. Exactly the shape we differentiated in the (x − 3)2 example, just with vectors.

Matrix calculus, justified from scratch

Ordinary calculus differentiates one variable. Here we differentiate with respect to a whole vector w at once — meaning we take ∂/∂wk for every k, and stack the results back into a vector. Two rules cover everything we need:

Rule 1 — linear term
d(wTa) / dw = a
wTa = a1w1 + a2w2 + ... + apwp
∂/∂wk [wTa] = ak (for every k) → stack all p of these → the vector a
Rule 2 — quadratic term (A symmetric)
d(wTAw) / dw = 2Aw
wTAw = ΣiΣj wiAijwj → ∂/∂wk = 2(Aw)k for every k when AT = A → the vector 2Aw
Applying both rules to J(w)
Match the middle term −2wTXTy to Rule 1, with a = XTy. Match the last term wTXTXw to Rule 2, with A = XTX — which is symmetric, since (XTX)T = XT(XT)T = XTX.
∂J/∂w = 0 − 2XTy + 2XTXw
The constant term yTy has no w in it, so its derivative is simply 0.

The same principle from Step 1 — just with vectors now

6.1
Set ∂J/∂w = 0
−2XTy + 2XTXw = 0
6.2
Divide every term by 2
−XTy + XTXw = 0
6.3
Move XTy to the other side
XTXw = XTy
6.4
Multiply both sides by (XTX)−1
(XTX)−1(XTX)w = (XTX)−1XTy
(XTX)−1(XTX) cancels out to the identity matrix, leaving just w on the left.
w = (XTX)−1XTy
★ derived — not assumed. Every step above followed from ordinary algebra and two calculus rules.

🔭 Gradient descent vs closed form

Take any cost function of a weight, J(w) — the same bowl we've been staring at. There are two completely different ways to find its lowest point: gradient descent — walk downhill, step by step — or the closed form just derived — calculate the bottom directly. The closed form is exact and needs no learning rate or iterations, but it requires inverting XTX, which gets expensive as the number of features grows — that's exactly where gradient descent earns its keep in practice.
