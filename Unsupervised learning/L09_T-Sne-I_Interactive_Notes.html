00 · one-paragraph bridge

Where PCA left us

Classes 08–09 built PCA end to end: standardize, project, maximize variance, land on eigenvectors ranked by how much spread each one captures. It's fast, exact, and reversible.

The limitation we ended on PCA optimizes exactly one thing — global variance. It has no notion of "who is near whom." Two points that were each other's closest neighbors in high-D can land far apart after a PCA projection, and two points that were never close can land on top of each other — simply because PCA was never asked to care about that in the first place. When the goal is specifically visualization — trusting the 2D picture to show you which points genuinely belong together — that gap matters a lot.

That gap is exactly where today's class begins.

01 · motivation

Why do we need t-SNE?

Same starting point as PCA — data with too many dimensions to look at — but a different promise about what survives the trip down.

Suppose you have 10,000 customers, each described by 100 features — spending habits, browsing behavior, demographics, and so on:

the setup
$$X \in \mathbb{R}^{100} \qquad\qquad 10{,}000 \text{ points} \qquad\qquad 100D \rightarrow 2D$$

You want to see this data — spot natural groupings, sanity-check a clustering result, present it to a room of non-technical stakeholders. But nobody can look at a 100-dimensional scatter plot. So, exactly like Class 08's opening move, you want to compress to 2D. PCA can do this compression. So here's the obvious question:

Why don't we just use PCA? — the question this entire class answers
The concrete use case to hold in your head Say your 10,000 customers form 3 natural behavioral groups. You want a 2D picture where — above everything else — points from the same group land near each other, and points from different groups land apart. Not "the two axes with the most spread" (that's PCA's promise). Specifically: if two customers were neighbors in the original 100D space, keep them neighbors on the page. That single requirement is the whole point of this class.

03 · the real fork in the road

PCA's question vs. t-SNE's question

Every property that follows — good and bad, for both methods — traces back to this one difference.

PCA asks
"Which direction captures the maximum variance?"
Variance → Optimization → Eigenvectors → Principal Components
vs
t-SNE asks
"If two points are neighbors in the original high-dimensional space, can I keep them neighbors on my 2D map?"
Neighbors → Similarity → Probability → Preserve relationships → 2D map
The single distinction that explains everything today There is no variance being maximized anywhere in t-SNE. No eigenvectors, no covariance matrix, no wᵀΣw. The entire worry is: for every point, who are its neighbors, and did the 2D map keep them close? That's it. Once this lands, every formula in this class is just this sentence being made precise.

Why this happenedThe true separating signal was real but small compared to the noise in other dimensions. PCA's #1 rule is "maximize variance" — so it happily built its top axis almost entirely out of noise, because noise had more spread than signal. t-SNE never asked "which direction has the most spread." It asked "who is near whom," and same-group points really were each other's neighbors in the original 5D space — so that's exactly what survived onto the page.
05 · a subtlety worth seeing early

Two different t-SNE runs, same neighbors

Run t-SNE twice on the identical dataset with two different random starting points. The two pictures will not look alike — and that's expected, not a bug. Math for exactly why comes over the next several sections.

Dataset: 42 points, 3 well-separated groups, 8 real dimensions this time (mimicking "100 features," just smaller so we can compute it by hand later). Same data, two runs:

Run 1 (seed 1) — blue top, coral bottom-left, green bottom-right.

Different picture, same storyNotice the overall orientation, rotation, and which corner each group lands in are completely different between the two runs. (For contrast: plain PCA on this same dataset preserves only 39.7% of that same neighbor structure.) Whoever was close in high-D is close again in 2D — that's the invariant. The layout around it is free to rotate.

Why is t-SNE's layout allowed to rotate freely, when PCA's isn't?

PCA's two axes are not arbitrary — they're literally directions inside the original 5D/8D space: PC1 is "the one specific combination of the real input features with the most variance," computed once, deterministically, from the covariance matrix. Run PCA again on the exact same data and you get back the same axes (at most flipped in sign — mirrored, never freely rotated). So a PCA plot's orientation actually carries meaning: "further along the x-axis" always corresponds to the same fixed blend of your original features.

t-SNE has no such anchor. Its entire objective (built up fully starting next class) only asks one question: do the relative distances between points on the 2D map match their relative closeness in high-D? Nothing in that question cares which direction is called "up," or where the origin sits. Pick up the finished 2D layout and rotate it, mirror it, or slide it — every pairwise distance on the page stays exactly the same, so the objective literally cannot tell the two versions apart. t-SNE starts from random noise and gradient-descends into whichever equally-valid orientation it happens to land in — which is why two different random seeds gave two visibly different (but equally correct) pictures above.

Orientation A — three points, three pairwise distances.
Orientation B — same three points, rotated ~125° and mirrored. Same three pairwise distances (4.12, 3.72, 3.35).
The practical consequenceTo an objective that only reads pairwise distances, these two triangles are identical — only their orientation on the page differs. Never read meaning into t-SNE's absolute axes, angles, or "up/down" — only into which points cluster together and how far apart clusters sit. PCA's axes, by contrast, really do correspond to fixed directions in your original features.

07 · the translation problem

Turning "close" into math

A computer cannot act on the sentence "B is pretty close to A." It needs a number.

We already have a number that captures closeness: Euclidean distance — the exact same "straight-line distance" formula from 2D or 3D geometry, it just also works in higher dimensions. So the very first move is trivial — for our worked running example (a point A, with 5 other points B, C, D, E, F around it, in some high-dimensional space), just measure how far each one is:

Euclidean distance — yes, this is the same formula as always
$$d(A,B) = \|x_A - x_B\| = \sqrt{\sum_{k=1}^{n} (x_{A,k}-x_{B,k})^2}$$
PieceWhat it means
xA, xBthe full coordinate vectors of points A and B — one number per dimension (n dimensions total, e.g. n = 5 or n = 100)
xA,k − xB,khow far apart A and B are along just one dimension k
Σ(...)²square each per-dimension gap (so negatives don't cancel) and add them all up, across all n dimensions
√(...)undo the squaring, back to an actual distance

In 2D this is the exact formula you already know — √((x₁−x₂)² + (y₁−y₂)²) — just with 2 terms instead of n. Nothing new is being invented here; t-SNE only needs this one familiar number as its starting point.

But raw distance has an awkward property for what comes next: it points the wrong way. "Close" should mean a big number (strong relationship); distance gives small numbers for close points. We want the opposite convention — so the real goal is:

the actual goal for this section
$$\text{Distance} \;\longrightarrow\; \text{Similarity}$$

08 · the tempting shortcut

Why not just 1/distance?

The simplest function with that "flips small↔big" shape is 1/d. It's worth trying — and worth seeing exactly why t-SNE doesn't stop there.

PointDistance from A1/distance
B0.6161.62
C0.6781.48
D13.8560.072

It does technically work: closer → bigger number, farther → smaller number. But it has real problems as a foundation to build a whole algorithm on:

Blows up at d=0

Two points at (nearly) the same location send 1/d toward infinity — an unbounded, badly-behaved value right where we most need stability.

No natural probability

t-SNE ultimately wants these numbers to become a normalized probability distribution. 1/d has no natural connection to any probability model — we'd be bolting one on.

No control over "how local"

Crucially, 1/d gives every point the same shape of decay. We're about to need each point to have its own, adjustable notion of "nearby" — Section 11 is the whole reason this matters.

What we actually wantA smooth, well-behaved function that turns distance into something that already looks and behaves like a building block of a probability — bounded, peaked at 0, smoothly decaying, and with a built-in "width" knob. That description is, almost word for word, the Gaussian (normal) curve.
09 · the actual function

The Gaussian similarity formula, piece by piece

One formula, unpacked term by term until nothing is mysterious.

t-SNE's similarity function
$$\text{similarity}(i,j) = \exp\!\left(-\dfrac{d(i,j)^2}{2\sigma_i^2}\right) = e^{-\frac{\|x_i - x_j\|^2}{2\sigma_i^2}}$$
SymbolWhat it is
d(i,j)Euclidean distance between points i and j — same distance as always
σᵢa "width" belonging to point i — how far its notion of "nearby" reaches (built up fully in Section 11)
exp(...) = e^(...)the exponential function — always positive, and it shrinks fast as its input goes more negative

Check 1 — what happens at distance 0?

StepDo thisResult
1Set d = 0 (two identical points)$e^{-0^2/2\sigma^2}$
2Simplify the exponent$e^0$
3Any number to the power 0 is 1$\boxed{\text{similarity} = 1}$
Maximum possible similarity, exactly 1 — two identical points are perfectly similar. No blow-up, unlike 1/d.

Check 2 — what happens as distance grows?

StepDo thisResult
1As d increases, d² increases$d^2 \uparrow$
2The exponent has a minus sign in front$-\dfrac{d^2}{2\sigma^2}$ becomes more negative
3e raised to an increasingly negative number shrinks toward 0$e^{\text{more negative}} \downarrow$
The minus sign is the entire mechanism: it converts "farther away" into "smaller and smaller e-power," which is exactly the decaying-similarity shape we wanted.
Memory trickThe minus sign makes distance hurt similarity. No minus sign, and this whole function would grow instead of decay — the single most important detail in the formula.
10 · the question worth asking

Why Gaussian, specifically?

Plenty of functions decay to zero. Here's what actually earns the Gaussian its place in this formula.

1 · Smooth and bounded everywhere

Unlike 1/d, it never explodes (capped at exactly 1) and never has a sharp corner or discontinuity. Every derivative exists everywhere — important later, once gradient descent needs to differentiate through this.

2 · A genuine probability density

The Gaussian isn't an arbitrary decaying curve — it is the normal distribution's shape. That means "normalize these similarity scores" (Section 12) isn't a hack; it's the natural, well-studied operation of turning a density into a probability.

3 · One adjustable width, per point

The Gaussian has exactly one shape parameter, σ, controlling how fast it decays. That's precisely the "dial" we need in Section 11 to let dense and sparse regions each get their own notion of "nearby."

4 · Matches the intuition we actually want

Very close points should be considered dramatically more similar than moderately close ones, with the effect fading gently at long range. The bell shape — sharp near the center, gentle tails — matches that intuition better than a straight line or a hard cutoff would.

Keep this in your pocket for next classThe low-dimensional side of t-SNE (Q, building the 2D similarities) deliberately does not reuse the Gaussian — it switches to the Student-t distribution instead, and that switch is precisely where the "t" in t-SNE comes from. The reason for that switch is a real, specific problem with using a Gaussian in low-D — saved for next class, once Q exists to explain it against.
11 · the parameter that does all the work

σ — each point's own notion of "nearby"

Think of σ as answering one question: how wide or narrow is my notion of "nearby"?

Small σ: similarity collapses to ~0 within a short distance. Only very close points count as neighbors.
Large σ: similarity decays much more slowly. Points quite far away still count as meaningfully similar.
Region A point sits inWhat that means for Aσ_A should be
Dense — lots of points packed nearbyDon't need to look far to find real neighborssmall
Sparse — points spread thinMust look farther to find any meaningful neighbor at alllarger
The Google Maps analogy In a crowded city, you can zoom in a lot and still see plenty of nearby places — you only need a small radius. In a remote area, you have to zoom out a long way before any other landmark shows up — you need a much larger radius. Two houses standing 100 meters apart are "pretty far" in a city where houses sit every 10 meters, but "very close" in a village where houses sit every 500 meters — the raw distance is identical, only the local context differs. That local context is exactly what σᵢ is built to capture.
The idea this is building towardOne fixed σ for the whole dataset can't be right — it would either be too small for sparse regions (barely any neighbors found) or too large for dense regions (everything looks equally "close," which destroys the fine local structure we actually care about). Every point needs its own σᵢ.

Tempting shortcut: why not just set σᵢ = distance to i's nearest neighbor?

Take two points and their distance to their single nearest neighbor:

PointDistance to nearest neighborNaive guess: σ = that distance
P1 (dense region)0.4σ_P1 = 0.4
P2 (sparse region)3.0σ_P2 = 3.0

This feels right — the dense point gets a small σ, the sparse point gets a bigger one, exactly the direction we want. So why doesn't t-SNE just do this?

Which neighbor, exactly?

Nearest? 2nd-nearest? Average of the closest 5? There's no principled reason to pick one specific distance — different choices hand back different σ, with no way to say which is "correct."

One number, zero context

This formula looks at exactly one distance and ignores the shape of everyone else nearby. One unusually close or far neighbor (noise, an outlier) swings σᵢ around wildly — it never looks at the full neighborhood, only a single point in it.

No dial for "how many neighbors"

You can't tell this formula "give every point roughly 30 effective neighbors" — distance and σ are locked together rigidly, with no way to steer the whole dataset toward one consistent standard.

What t-SNE does instead — flip the logic entirelyDon't compute σᵢ from a distance. Instead, fix a target — how many effective neighbors every point should end up with (this target is perplexity, introduced next) — and search for whichever σᵢ produces that target, using all of point i's distances at once, not just one. That search is the binary-search loop in Section 16, worked through with real numbers end-to-end in Section 17.
12 · from raw scores to a real distribution

From similarity to probability

Gaussian similarity scores are a great start, but they don't sum to 1 — so they aren't yet a probability distribution. One more step fixes that.

Take our running point A, distances to B, C, D, E, F, and a similarity computed with some σ_A. Suppose the raw scores come out as:

Why these aren't probabilities yetProbabilities must add up to exactly 1. These raw scores add up to 1.36 — they're just similarity scores, not yet a distribution. The fix is the most natural one possible: divide every score by the total.
normalization
$$p_{j|i} = \dfrac{\text{similarity}(i,j)}{\displaystyle\sum_{k \neq i} \text{similarity}(i,k)} = \dfrac{\exp\!\left(-\|x_i-x_j\|^2 / 2\sigma_i^2\right)}{\displaystyle\sum_{k \neq i} \exp\!\left(-\|x_i-x_k\|^2 / 2\sigma_i^2\right)}$$

$$p_{j|i} = \text{"probability of picking } j \text{ as a neighbor, given that we're standing at } i\text{"}$$
Each point gets its own distributionWe repeat this for every point, not just A. Point B gets its own row of probabilities p·|B, point C gets p·|C, and so on. Crucially, these are generally not symmetric: pB|A (how much A cares about B) need not equal pA|B (how much B cares about A) — A might sit in a dense crowd where B is just one of many close points, while B might sit in a sparse area where A is its single most important neighbor. Collectively, all these per-point rows together are what we've been calling P.
13 · putting σᵢ to work

Dense vs. sparse neighborhoods, formalized

Section 11 gave the intuition. Here's the same idea made completely concrete with the actual probability chain.

similarity, now written with i's own σ

Plugging this into the normalization from Section 12 gives the complete, final formula for one entry of P:

the complete p_{j|i}
$$p_{j|i} = \dfrac{e^{-\|x_i-x_j\|^2/2\sigma_i^2}}{\displaystyle\sum_{k\neq i} e^{-\|x_i-x_k\|^2/2\sigma_i^2}}$$

Restating the shift in thinkingWe've moved from the flawed idea "distance = similarity" to the correct one: "how important is this distance, relative to this particular point's own local neighborhood?" σᵢ is exactly what answers that — and that's the question we still need to answer: how does t-SNE actually pick a number for σᵢ?
14 · the missing piece

So how do we actually pick σᵢ? Entropy, then perplexity

With 10,000 points, nobody is hand-tuning 10,000 separate σ values. We need σᵢ to fall out of a single, simple choice — automatically, per point.

Start from a distribution we already have — say, point A's:

A's probability distribution
$$P_A = [\,p_{B|A},\ p_{C|A},\ p_{D|A},\ p_{E|A}\,] = [0.60,\ 0.25,\ 0.10,\ 0.05]$$

We need a number that measures: how spread out is this distribution? That's exactly what entropy measures.

Shannon entropy of a distribution
$$H(P_i) = -\sum_{j} p_{j|i}\, \log_2 p_{j|i}$$
Probability concentrated

B=95%, C=2%, D=2%, E=1%

→ low entropy. Almost all the "neighbor weight" sits on one point — a narrow, confident neighborhood.
Probability spread out

B=25%, C=25%, D=25%, E=25%

→ higher entropy. Weight is shared roughly equally — a wide, undecided neighborhood.
In one lineEntropy measures how spread out the probability distribution is. That's step one. Now convert it into something with a much more intuitive scale:
entropy → perplexity
$$\text{Perplexity}(P_i) = 2^{H(P_i)}$$
Example distributionH (entropy)Perplexity = 2^HInterpretation
[0.25, 0.25, 0.25, 0.25]2.004"4 equally important neighbors"
[0.20, 0.20, 0.20, 0.20, 0.20]2.325"5 equally important neighbors"
the intuitive reading
$$\text{Perplexity} = \text{"how many equally-important neighbors would this distribution roughly correspond to?"}$$
15 · making it concrete

Perplexity in plain English

Strip away the formula for a second. In practice, perplexity is a single dial that controls the size of the neighborhood every point gets to see.

The one sentence to remember

Perplexity is (roughly) "how many neighbors each point should pay attention to." Set perplexity = 30, and t-SNE tries to give every single point — whether it lives in a crowded region or an empty one — a probability distribution that behaves as if it has about 30 meaningfully close neighbors.

See it directly: the same 3-group, 42-point dataset from Section 05, run at three different perplexity values.

Perplexity = 2 (too low). Each true group fractures into two or three tighter sub-pieces — one blue/coral point even gets stranded off on its own. The algorithm is only trying to satisfy ~2 neighbors per point, so it fixates on tiny sub-cliques.
Perplexity = 8 (well-matched to this data). All three true groups come through as one single, tight, cleanly separated cluster each — exactly the structure that's actually there.
Perplexity = 35 (too high for only 42 points). Each point is now forced to treat roughly 35 of the other 41 points as "meaningful neighbors" — nearly the whole dataset. The 3 groups are still discernible, but boundaries blur and internal structure compresses toward uniform.
Reading the three panels togetherToo-low perplexity makes the map obsess over tiny local cliques and fracture real groups apart. Too-high perplexity forces every point to consider far more of the dataset as "close," blurring genuinely separate groups toward each other. A well-matched perplexity (roughly: comfortably smaller than your total number of points, and in the right ballpark for your true group sizes) is what lets the natural structure come through cleanly — exactly what perplexity = 8 shows here.

The simplest possible way to picture perplexity

Forget the formula for a moment. If a point's probability distribution pj|i came out perfectly clean, perplexity would just be a head-count:

If perplexity ≈The probabilities would look likeReading it
20.50, 0.50, 0, 0, 0, ..."2 points share essentially all the weight — 2 real neighbors, everyone else ≈ irrelevant"
30.33, 0.33, 0.33, 0, 0, ..."3 points share the weight equally — 3 real neighbors"
300.033 × 30, 0, 0, ..."30 points share the weight equally — 30 real neighbors"

Real distributions are messier than this (weight trails off gradually rather than cutting to a hard 0 — see the σ = 5, 10 rows back in Section 09's table), but this idealized picture is exactly what perplexity is trying to summarize in one number: roughly how many points does this distribution treat as genuine neighbors?

Now the real payoff — the whole reason σᵢ exists per-point: two points can sit in completely different neighborhoods, need completely different σ, and still land on the exact same perplexity, because perplexity is a target on the shape of the distribution, not on distance itself.

Dense point P1 — nearest neighbors at distances 0.4, 0.5, 0.6. Needs only σ ≈ 0.98 to reach perplexity = 3.
Sparse point P2 — nearest neighbors at distances 3.0, 3.6, 4.2 (much farther away in absolute terms). Needs a much bigger σ ≈ 4.16 to reach the same perplexity = 3.
Same target, wildly different σ, same-shaped resultP1's real neighbors are under 1 unit away; P2's real neighbors are 3–4 units away — roughly 7× farther in raw distance. Yet both end up with almost the identical probability shape (≈0.35 / 0.33 / 0.32 / ≈0 vs ≈0.37 / 0.33 / 0.29 / ≈0) because each point used its own σ to reach the same perplexity = 3 target. This is the entire point of per-point σᵢ: perplexity fixes "how many neighbors count," and σᵢ is whatever each point individually needs to make that true, regardless of how close or far those neighbors happen to sit in absolute terms.
16 · optional, self-read

How is σᵢ actually found, internally?

You choose one perplexity for the whole run. The algorithm still has to solve, separately for every single point, "what σᵢ gives me a distribution whose perplexity matches my target?" Here's the loop that does it — not required for using t-SNE, just satisfying to know it isn't magic.

A small search loop, repeated independently for every point, until each point's own perplexity lands close to the one target value you chose.
the rule in one line
$$\text{Distances} \to \text{try } \sigma_i \to \text{probabilities} \to \text{perplexity} \to \text{adjust } \sigma_i \to \dots \to \text{perplexity} \approx \text{target}$$
This runs once per point before any 2D optimization starts — it's entirely about building P (today's whole job), and finishes long before Q, KL divergence, or gradient descent (next class) ever begin.

18 · the payoff

The key idea: we fix perplexity, not σ

This is the single most important practical fact from today, worth isolating on its own.

What we do NOT do
Manually pick 10,000 separate σ values, one per point, by hand-inspecting each point's local density.
instead
What t-SNE actually does
You choose one hyperparameter — perplexity — and the binary-search loop (Section 16) solves for every σᵢ automatically, per point.
the four-line summary
You choose ONE perplexity
Each point gets its OWN σᵢ
Each point has its OWN entropy
Each point's entropy corresponds to the SAME target perplexity
Why this is better than fixing σ globallyWhy this is better than tuning σ by hand
A single global σ can't serve both dense and sparse regions well (Sections 11 & 13) — perplexity adapts σ automatically, per point, to local densityOne human-interpretable number ("roughly how many neighbors matter") replaces thousands of arbitrary, uninterpretable radii nobody could reasonably set by hand
The practical rule of thumbTypical perplexity values in practice sit in the 5–50 range, and — as Section 15's sweep showed directly — should generally stay well below your total number of points, or the algorithm runs out of genuinely distinct neighbors to satisfy.

Everything today, one picture

Sections 00–03
PCA optimizes global variance and has no notion of neighbors. t-SNE's entire question is instead: if two points were neighbors in high-D, are they still neighbors in 2D?
Sections 04–05
Proven on real data: t-SNE separates genuinely-clustered data ~3.6× better than PCA when the separating signal has low variance. Two different t-SNE runs land in different orientations but preserve ~74% of true neighbor structure either way (vs. 40% for PCA).
Section 06
The full pipeline: Distance → Similarity → Probability → P (today) → random 2D → Q → KL divergence → gradient descent → final map (next class).
Sections 07–10
"Close" becomes a number via Euclidean distance, then a well-behaved similarity via a Gaussian: e^(−d²/2σ²) — bounded, smooth, and a genuine probability density, unlike 1/d.
Sections 11–13
Every point gets its own σᵢ — small in dense regions, large in sparse ones — so "nearby" is always judged relative to local density, not one global ruler.
Section 12
Raw Gaussian scores don't sum to 1 — dividing by their total turns them into a real, per-point probability distribution pj|i, generally asymmetric between i and j.
Sections 14–16
Entropy measures how spread a distribution is; Perplexity = 2^H converts that into "effective neighbor count." A binary search per point finds the σᵢ that hits one chosen target perplexity.
Sections 17–18
Worked end to end on 6 real points: dense-cluster point A converges to σ≈2.47, sparser-cluster point D converges to σ≈2.84 — same target perplexity, genuinely different widths. You fix ONE perplexity; the algorithm finds every σᵢ.
The one-paragraph version

t-SNE starts by asking, for every point, who its real neighbors are back in the original high-dimensional space — measured as distance, converted into a Gaussian similarity that decays smoothly to zero, then normalized into a proper probability distribution. Because "nearby" means something different in a crowded region than in an empty one, every point gets its own neighborhood width σᵢ, and rather than guessing that width by hand, we fix one interpretable number — perplexity, "how many neighbors should matter" — and let a small search find the σᵢ that delivers it, point by point. The result, P, is a complete, high-fidelity description of the neighborhood structure in the original data — and next class, we build its low-dimensional twin, Q, and spend the rest of the algorithm dragging Q into agreement with P.
