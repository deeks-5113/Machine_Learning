01 · orientation

Supervised learning needs an answer key. This problem doesn't have one.

Every supervised model you've built so far — logistic regression, KNN, Decision Trees, the full GBDT stack — learned a mapping because someone already knew the right answer for every training row. Fraud / not-fraud. Default / no-default. Spam / not-spam. That ground truth is exactly what the loss function compares its prediction against.

Today we start a different family of problems. ClusterMart's database has millions of customer rows — spend, frequency, discount usage — but no "customer type" column has ever existed. Nobody labelled it. There's nothing to compare a prediction to. This is unsupervised learning: finding structure that's already sitting inside the data, without being told what the structure should look like.

Supervised learning

  • Data arrives as pairs \((X, y)\)
  • \(y\) already exists — a human labelled it, or an event resolved it (chargeback happened, email was reported as spam)
  • Goal: learn \(f(X) \approx y\)
  • Success is checkable — compare the prediction to the known answer
  • You are told the categories up front
vs

Unsupervised learning

  • Data arrives as \(X\) only — no \(y\) column exists
  • Nobody has ever labelled "customer type" for these rows — the decision doesn't exist yet
  • Goal: discover structure already present in \(X\)
  • Success is judged geometrically — how tight and how separated are the groups?
  • You may not even know how many categories there should be
Why you can't just hand-label it. Millions of customers, no analyst has ever sat down and tagged each one — and even if they tried, what are the "correct" categories in the first place? That decision doesn't exist yet. This is not a labelling backlog waiting to be cleared; it's an absence of ground truth. Clustering is how we let the data itself propose the categories.

The two questions that separate the two worlds

QuestionSupervised learningUnsupervised learning
What is the input?Features \(X\)Features \(X\)
What is the target?\(y\) exists and is knownNo \(y\) — nothing to predict
What does the model output?A prediction to compare against \(y\)Groupings / structure / compressed representation
How do you check correctness?Accuracy, precision, log-loss vs. the known labelGeometric quality — tightness, separation (no ground truth to score against)
Example algorithmsLogistic Regression, Random Forest, XGBoostK-Means, DBSCAN, GMM, PCA
02 · where this shows up at scale

Six places top companies run clustering in production

In every case below, notice the same pattern: rich behavioural data exists, but no pre-existing "type" column ever did — the grouping itself is the discovery, not a lookup.

Spotify

Groups listeners by taste signals — skip rate, genre mix, replay behaviour, time-of-day listening — to power Discover Weekly and Daily Mixes.

No "taste persona" label exists anywhere in the raw logs — taste is inferred from behaviour, never assigned by a human.
Netflix

Clusters viewing behaviour into "taste communities" that cut across age, geography, and demographics entirely.

Two 34-year-olds in the same city can land in completely different clusters — demographics were never the real signal.
Amazon

Segments buyer and merchant behaviour to feed the same fraud/risk family of pipelines you studied in Supervised Learning — anomalous behavioural clusters trigger review queues.

Fraud rings are found by clustering unusual behaviour together; they are never pre-labelled before they're caught.
Google Photos

Groups faces across your entire library into "this is probably the same person" clusters — before you've ever typed a name.

The identity label only gets attached after you confirm a cluster — clustering runs completely label-free.
Uber

Clusters pickup/drop-off geo-density in real time to decide dynamic surge-pricing zones and driver repositioning.

"Zones" aren't administrative boundaries drawn by a human — they emerge purely from demand density.
PayPal / Visa

Segments merchant transaction-behaviour patterns to build risk-tier baselines before any chargeback has ever occurred.

A brand-new merchant has zero label history on day one — clustering supplies a prior from behaviour alone.
The common thread. In every example, waiting for labels would mean waiting forever — either because labelling millions of rows by hand doesn't scale, or because the "correct" category genuinely doesn't exist until the data itself reveals it.
03 · today's problem statement

ClusterMart: segment customers with zero labels

ClusterMart is an e-commerce platform. Marketing wants to run different campaigns for different customer types — but the only thing in the database is raw behaviour: annual spend and purchase frequency. No "segment" column has ever existed.

"We have millions of customers, but no 'customer type' column. We want to run Premium-customer campaigns differently from Discount-Hunter campaigns — but nobody has ever labelled who belongs to which group." — ClusterMart, VP Marketing

What marketing suspects (but can't prove)

  • Premium customers — high spend, moderate frequency
  • Frequent / repeat buyers — high frequency, moderate spend
  • Big billion-day shoppers — spend spikes only during mega sale events
  • Moderate / occasional buyers — low on both axes

What we actually have

  • Two numeric columns per customer: spend, frequency
  • Zero ground-truth segment labels
  • A business need for some number of actionable groups — not necessarily 4, that number is itself something we'll have to justify (Section 21)
This is exactly the setup clustering is built for. We have $X$ (spend, frequency) and no $y$. Our job for the rest of this class: let the geometry of the data propose the groups, then formalise "propose" into an algorithm — K-Means.

What is clustering? Start by looking, not computing

1

2
Why those three? Not because of colour or a label — because points inside each group sit close together, and the three groups sit far apart from each other.
3

Same 18 points — visual grouping applied. Three points (blue) are ambiguous, sitting between groups. We'll come back to exactly these boundary cases in Section 11.
Clustering, informally. Group data points so that points within a group are more similar to each other than to points in other groups — using only raw features, no labels. "Similar" here means geometrically close.
05 · making "similar" precise

Intra-cluster vs inter-cluster distance

"Closely packed" and "far apart" are doing a lot of informal work. Let's name them properly — this pair of ideas is what every clustering quality metric in this course (WCSS, Silhouette) is built from.

Intra-cluster distance

How spread out points are within the same cluster. Distance from points to each other (or to their centroid) inside one group.

We want this small — tight, compact groups.

Inter-cluster distance

How far apart different clusters are from each other — typically measured centroid-to-centroid.

We want this large — clearly separated groups.
the one-line goal of every clustering algorithm \[ \boxed{\text{minimise intra-cluster distance} \quad\text{and}\quad \text{maximise inter-cluster distance}} \]
Intuition anchor. A cluster is "good" when a random member is much closer to its own clustermates than to anyone in a different cluster. That gap — tight inside, wide between — is precisely what Silhouette Score will measure numerically in Section 17.

07 · from intuition to algorithm

If you had to automate this yourself — what would you write?

"If you had to automate this clustering process yourself — write out the steps — what would you do?" — the exercise every learner should try before reading further

Try it before reading on. Most people who reason it through by hand independently arrive at something like this:

1
Pick some starting "center" points. You don't know the true groups yet, so start anywhere reasonable.
2
Assign every customer to their nearest center. "Nearest" needs a distance rule — we'll fix that in Section 9.
3
Now that each center has members, recompute the center as the average position of its members — the center should sit in the middle of the people assigned to it, not wherever it started.
4
Centers moved — so some customers might now be closer to a different center. Re-check every assignment.
5
Repeat steps 3–4 until nothing changes anymore.
You just invented K-Means. That five-step loop — pick centers, assign, recompute, reassign, repeat until stable — is the entire algorithm. Everything from here is just making each step mathematically precise.
08 · new term

What exactly is a centroid?

A centroid is simply the mean position of every point currently assigned to a cluster — one coordinate per feature, each computed independently as a plain average.

centroid — general form, n points, d dimensions \[ \boxed{\;\text{centroid} = \left(\frac{1}{n}\sum_{i=1}^n x_i^{(1)},\ \frac{1}{n}\sum_{i=1}^n x_i^{(2)},\ \dots,\ \frac{1}{n}\sum_{i=1}^n x_i^{(d)}\right)\;} \]

2D — the case we'll use all class (spend, frequency)

Cluster A has three customers: \((2,3)\), \((3,4)\), \((2,5)\).

\[ C_A = \left(\frac{2+3+2}{3},\ \frac{3+4+5}{3}\right) = (2.33,\ 4.00) \]
The centroid (diamond) sits at the mean of the three teal points — not necessarily on top of any real customer.

3D — add a third feature, e.g. discount-usage %

Same idea, one more coordinate. Cluster with points \((2,3,10)\), \((3,4,14)\), \((2,5,12)\):

\[ C = \left(\frac{2+3+2}{3},\ \frac{3+4+5}{3},\ \frac{10+14+12}{3}\right) = (2.33,\ 4.00,\ 12.00) \]

4D — add a fourth feature, e.g. days-since-last-purchase

Points \((2,3,10,5)\), \((3,4,14,8)\), \((2,5,12,6)\):

\[ C = \left(\frac{2+3+2}{3},\ \frac{3+4+5}{3},\ \frac{10+14+12}{3},\ \frac{5+8+6}{3}\right) = (2.33,\ 4.00,\ 12.00,\ 6.33) \]
The pattern never changes. Whether it's 2 features or 200, a centroid is computed the exact same way: average each column independently across all points currently assigned to that cluster. Dimensionality changes nothing about the mechanics — only how many numbers you're averaging in parallel.
09 · new term

Distance metrics — how do we define "nearest"?

Step 2 of our invented algorithm said "assign every point to its nearest center." We need to pin down what "nearest" means. The default, and the one K-Means uses, is Euclidean distance.

Euclidean distance — general, d dimensions \[ \boxed{\;d(p,q) = \sqrt{(p_1-q_1)^2 + (p_2-q_2)^2 + \dots + (p_d-q_d)^2} = \sqrt{\sum_{k=1}^{d}(p_k-q_k)^2}\;} \]

Worked example — customer A \((1.0, 2.0)\) vs customer B \((1.5, 2.3)\) vs customer C \((6.0, 7.0)\):

PairCalculationDistance
A → B\(\sqrt{(1.0-1.5)^2+(2.0-2.3)^2}\)0.58 — very close
A → C\(\sqrt{(1.0-6.0)^2+(2.0-7.0)^2}\)7.07 — far
Reading it. A and B are almost the same customer behaviourally; C is a completely different segment. Euclidean distance turns that intuition into one comparable number.

Other distance metrics — and when each is the right choice

MetricFormula (2D)Geometric pictureUse it when…
Euclidean\(\sqrt{\sum(p_k-q_k)^2}\)straight-line "as the crow flies"continuous numeric features, no directional structure — K-Means' default, and what we use today
Manhattan (L1)\(\sum|p_k-q_k|\)grid-city / taxicab pathhigh-dimensional or grid-like movement (e.g. city-block delivery routing); more robust to outliers than Euclidean
Cosine similarity\(\dfrac{p\cdot q}{\lVert p\rVert\lVert q\rVert}\)angle between vectors, ignores magnitudetext / embeddings / ratings where direction matters more than raw scale — e.g. two users who rate everything 1 point apart but proportionally identical
Minkowski\(\left(\sum|p_k-q_k|^p\right)^{1/p}\)generalises Euclidean (\(p{=}2\)) and Manhattan (\(p{=}1\))when you want a tunable middle ground
Hammingcount of differing positionsbit-flip distancecategorical / binary features (e.g. one-hot encoded flags)
For today's dataset. Spend and frequency are both continuous numeric features with no directional or categorical structure — Euclidean distance is the natural and standard choice, and it's what sklearn's KMeans uses internally.
10 · formalising the algorithm

The K-Means algorithm, precisely

Now that centroid and distance are both precise, here is the loop from Section 7 written formally.

1
Choose K. You must decide the number of clusters before the algorithm runs — K-Means cannot discover K on its own. (How to choose K well is Section 21 — for now, assume it's given.)
2
Initialise K centroids. Commonly K real data points chosen at random (what we'll do today), or K random positions in feature space.
3
Assignment step. For every point, compute its Euclidean distance to all K centroids; assign it to the nearest one.
4
Update step. Recompute each centroid as the mean of the points currently assigned to it.
5
Reassign. Centroids moved in step 4 — re-run the assignment step against the new centroid positions.
6
Converge. Repeat steps 4–5 until assignments stop changing (or centroids move by less than a tiny threshold). That's convergence.
convergence check, exactly what sklearn does internally \[ \lVert \text{centroids}_{\text{new}} - \text{centroids}_{\text{old}} \rVert < \varepsilon \quad\Rightarrow\quad \text{stop} \]
Why K must be known upfront. Step 3's assignment rule literally needs K centroids to measure distance against — the algorithm has no mechanism to spawn or delete a cluster mid-run. Choosing K is a separate decision, made before K-Means starts (Section 21).
from sklearn.cluster import KMeans model = KMeans(n_clusters=3, init='random', n_init=10, random_state=42) model.fit(X) # runs steps 2-6 internally labels = model.labels_ # cluster assigned to each point centroids = model.cluster_centers_ wcss = model.inertia_ # Section 13

Let's now run every one of these steps completely by hand — no shortcuts — so every distance and every mean is visible.

12 · what we have now

After convergence: what does K-Means actually hand back?

Once the loop stops, two artefacts exist — and that's all K-Means ever produces:

1 · K cluster centroids

Three coordinate pairs: \((1.8,1.8)\), \((8.2,2.8)\), \((5.19,6.69)\) — the "typical customer" of each segment.

2 · A cluster label per point

Every one of the 18 customers now carries a single integer label \(\{1,2,3\}\) — the closest thing we have to a "customer type" column, entirely self-generated.

Notice what's missing. K-Means never tells you what a cluster "means" in business terms — it only hands back coordinates and a group number. Turning "Cluster 1 = centroid at (1.8, 1.8)" into a business-readable name like "Premium" or "Discount-Hunter" is a separate interpretation step, deliberately saved for next class.
13 · new term

WCSS — Within-Cluster Sum of Squares

We have clusters. Now: how do we say, numerically, that this clustering is "good"? The first metric is WCSS — it directly measures the intra-cluster distance idea from Section 5.

WCSS — sum over every cluster, every point in it \[ \boxed{\;WCSS = \sum_{k=1}^{K}\ \sum_{p\,\in\,\text{cluster }k} \lVert p - C_k \rVert^2\;} \]
NameWhere you'll see it
Within-Cluster Sum of Squares (WCSS)the formal, textbook name
Inertiamodel.inertia_ — sklearn's attribute name for exactly this quantity
SSE (sum of squared errors)sometimes used interchangeably, borrowed from regression
Intra, not inter. WCSS only measures spread within clusters — it says nothing about how far apart different clusters are from each other. It is a pure intra-cluster metric. (Silhouette Score, Section 17, folds in the inter-cluster side too.)

Verifying WCSS on our worked example

\[ WCSS = \underbrace{(1.22^2{+}0.82^2{+}\dots)}_{\text{Cluster 1, 5 pts}} + \underbrace{(1.22^2{+}0.82^2{+}\dots)}_{\text{Cluster 2, 5 pts}} + \underbrace{(1.77^2{+}0.36^2{+}\dots)}_{\text{Cluster 3, 8 pts}} \] \[ = 5.60 + 5.60 + 25.94 = \mathbf{37.14} \]
# manual verification — matches model.inertia_ exactly wcss = sum((p - centroid[label(p)])**2 for p in all_points).sum() # -> 37.14
Why "inertia"? Borrowed from physics — moment of inertia measures how spread out mass is around a center of rotation, \(I=\sum m_i r_i^2\). WCSS has the exact same shape (mass = 1 per point), which is why sklearn's attribute is literally named inertia_.
14 · building intuition

The village milkman analogy — why WCSS always falls as K rises

A village has 100 houses scattered across town. A milkman is stationed at a depot and delivers to every house from there — the total "distance travelled" is exactly the WCSS idea, with the depot playing the role of a centroid.

1 milkman, 100 houses

One depot at the centre of the village. Every house is served from the same point — some deliveries are very long.

2 milkmen, 100 houses

Village splits into two zones, each with its own depot near its own centre. Average delivery distance drops immediately.

3, 4, 5… milkmen

Each new depot serves a smaller, tighter zone. Distances keep shrinking — but so does the operational sense of adding yet another milkman.

100 simulated village houses. WCSS: K=1 → 1613, K=2 → 943, K=3 → 519, K=5 → 313, K=10 → 120, K=50 → 9, K=100 → 0.

The trap. WCSS always decreases as K increases — it hits exactly zero when K = number of points (every point is its own centroid). So we can never choose K by minimising WCSS alone; a village with 100 milkmen is "perfect" delivery and a nonsensical business. This is exactly why Section 21 needs the elbow, not the minimum.
15 · why the algorithm works

Why does the update step use the mean? A derivation.

K-Means' update step recomputes each centroid as the mean of its members. This isn't a convenient guess — the mean is provably the single point that minimises WCSS for a fixed set of members. Here's the derivation.

Derive: which point \(c\) minimises \(\sum_i \lVert x_i - c\rVert^2\) ?

Fix a cluster's membership \(\{x_1,\dots,x_n\}\) and treat the centroid \(c\) as the only unknown. WCSS contribution from this one cluster (1D for clarity — the same holds independently per coordinate in higher dimensions):

\[ J(c) = \sum_{i=1}^n (x_i - c)^2 \]

Differentiate with respect to \(c\) and set to zero — the standard first-order condition for a minimum:

\[ \frac{dJ}{dc} = \sum_{i=1}^n 2(x_i-c)(-1) = -2\sum_{i=1}^n (x_i - c) = 0 \] \[ \Rightarrow\quad \sum_{i=1}^n x_i = \sum_{i=1}^n c = nc \quad\Rightarrow\quad c = \frac{1}{n}\sum_{i=1}^n x_i \]

The second derivative \(\dfrac{d^2J}{dc^2}=2n>0\), confirming this is a minimum, not a maximum. So:

\[\boxed{c^{*} = \bar{x} = \frac{1}{n}\sum_{i=1}^n x_i \quad\text{— the mean, exactly}}\]
This is the whole reason the update step is a mean. Given a fixed set of members, the mean is mathematically guaranteed to be the single point minimising that cluster's contribution to WCSS. K-Means alternates: fix centroids → find best assignment (step 3); fix assignment → find best centroid, i.e. the mean (step 4). Each step can only decrease or hold WCSS steady — never increase it — which is exactly why the algorithm always converges.
16 · optional deep dive

What if we used a different distance metric?

Everything in this section is optional, curiosity-driven content — not required for the exam or next class. It answers a question sharp learners always ask: if Manhattan distance gives more outlier-robust clusters, why do we default to Euclidean K-Means at all?

The derivation in Section 15 was specific to squared Euclidean distance. Change the distance metric, and the mathematically "optimal" update step changes with it — the two are linked, not independent choices.

Distance metricOptimal update stepWhy
Euclidean (squared)MeanSection 15's derivation — minimises sum of squared deviations

Optional derivation — why does Manhattan distance give the median?

Derive: which point \(c\) minimises \(\sum_i |x_i - c|\) ?

Unlike squared error, \(|x_i-c|\) isn't differentiable exactly at \(c=x_i\), so we reason about the sign of the gradient instead of setting a derivative to zero.

\[ J(c) = \sum_{i=1}^n |x_i - c|,\qquad \frac{dJ}{dc} = \sum_{i=1}^n \text{sign}(c - x_i) \]

Each point contributes \(+1\) to the slope if \(c\) is above it, and \(-1\) if \(c\) is below it. \(J(c)\) is minimised exactly where these +1's and −1's balance — i.e. where half the points sit below \(c\) and half sit above. That balance point is, by definition, the median.

\[\boxed{c^{*} = \text{median}(x_1,\dots,x_n)}\]
Mean vs median, symmetrically. Mean minimises squared deviation (Euclidean → K-Means). Median minimises absolute deviation (Manhattan → K-Medians). Same proof technique, different distance, different optimum.

Optional — Manhattan/K-Medians is more robust to outliers. See it happen:

Take Cluster 1's five real members and add one corrupted entry — a data-logging glitch records a customer's frequency as 200 instead of 2:

PointsMean (K-Means style)Median (K-Medians style)
A,B,C,D,E — clean(1.80, 1.80)(2.00, 2.00)
A,B,C,D,E + 1 corrupted point (1, 200)(1.67, 34.83) — dragged wildly off(1.50, 2.00) — barely moves
This is the entire robustness argument in one table. One bad row single-handedly pulls the Euclidean mean almost 20× further from the true cluster center, while the median doesn't even notice it. Outliers have unbounded influence on a mean, but bounded influence on a median.

So why does K-Means stay the default? (Not "which is better" — which trade-off do you want?)

ConsiderationK-Means (Euclidean / mean)K-Medians (Manhattan / median)
Update-step cost\(O(n)\) — a running sum\(O(n\log n)\) — needs a sort, per dimension, every iteration

Relationship to variancemean minimising squared error = minimising variance — a very natural fit when clusters are roughly round/Gaussian-shapedno clean variance interpretation

The honest answer. K-Medians is better specifically when your data has heavy outliers or genuinely grid-like structure — that's a real, valid reason to reach for it deliberately. K-Means stays the default not because it's "better" in some absolute sense, but because clean data + speed + tooling maturity + the natural variance interpretation make it the right default choice most of the time. Choosing between them is a deliberate trade-off, not a correctness question.
17 · a sharper metric

Silhouette Score — for a single point

WCSS only looks inward (intra-cluster). Silhouette Score folds in both ideas from Section 5 — intra and inter — into one number per point, ranging from \(-1\) to \(+1\).

the two ingredients \[a(p) = \text{average distance from } p \text{ to every other point in its own cluster}\] \[b(p) = \text{average distance from } p \text{ to every point in its nearest other cluster}\] \[\boxed{\;s(p) = \dfrac{b(p) - a(p)}{\max(a(p),\,b(p))}\;}\]

Worked example — point B, from our 18-point clustering

B \((2,1)\) sits in Cluster 1 = \(\{A,B,C,D,E\}\). We need two numbers.

Step 1 — \(a(B)\): distance to every other point in its own cluster

PairDistance
d(B, A)1.414
d(B, C)2.000
d(B, D)1.414
d(B, E)1.000
a(B) = mean1.457

Step 2 — \(b(B)\): average distance to every other cluster, take the minimum

This is the part learners most often get wrong: \(b(p)\) is not a single number until you've computed the mean distance to each other cluster separately, then taken the smallest.

Other clusterMean distance from B
Cluster 2 = {F,G,H,I,J}6.505
Cluster 3 = {K,L,M,N,O,P,Q,R}6.601
b(B) = min of the two6.505
Why the minimum? \(b(p)\) represents the nearest rival cluster — the toughest competitor B would face if it were mis-assigned. Taking the minimum, not an average across all other clusters, is what makes Silhouette sensitive to the single most-similar alternative group.

Step 3 — combine

\[ s(B) = \frac{b(B)-a(B)}{\max(a(B),b(B))} = \frac{6.505 - 1.457}{\max(1.457,\,6.505)} = \frac{5.048}{6.505} = \mathbf{0.776} \]
Reading it already: B is roughly 4.5× closer to its own cluster than to the nearest rival — a strong, unambiguous assignment.

Contrast — our boundary customers P, Q, R

Recall these three sat visually between groups in Section 4, and R even flipped clusters mid-algorithm (Section 11). Their silhouette scores confirm the ambiguity numerically:

Reading the Silhouette Score: +1, 0, and negative

Negative silhouette in practice. This happens when K-Means' initialisation was unlucky, or when the true structure doesn't actually support K well-separated clusters. It's a direct, per-point diagnostic of assignment quality that WCSS alone can never give you — WCSS has no concept of "nearest rival cluster."
19 · scaling up

Silhouette Score for the entire dataset

One point's score is a diagnostic. The dataset's Silhouette Score is simply the average of \(s(p)\) across every point — one number summarising the whole clustering.

\[ \boxed{\;\text{Silhouette Score} = \frac{1}{n}\sum_{p=1}^{n} s(p)\;} \]

20 · a fair question

Isn't this wildly inefficient at scale?

For each point, \(a(p)\) needs distances to every other member of its own cluster, and \(b(p)\) needs distances to every point in every other cluster. That's a lot of pairwise distance computation. Let's be precise about how much.

cost per point, and for the whole dataset \[ \text{cost per point} \approx O(n) \quad\Rightarrow\quad \text{cost for all } n \text{ points} \approx O(n^2) \]
n (customers)Pairwise distance computations \(\approx n^2/2\)Practical?
18 (our example)153trivial
1,000~500,000still fine, sub-second
1,000,000 (ClusterMart's real scale)~500,000,000,000infeasible to run on every point, every time
Quadratic growth — doubling customers quadruples the pairwise-distance workload.

What's actually done in practice

1
Sample, don't compute on everyone. Run Silhouette on a random subsample (e.g. 5,000–10,000 customers) — the score is a reliable estimate of the full population's clustering quality without the full \(O(n^2)\) cost.
2
Use Silhouette for model selection, not production monitoring. It's typically run once, offline, while deciding K (Section 21) — not recomputed on every new customer in real time.
3
WCSS stays cheap. WCSS only needs each point's distance to its own centroid — that's \(O(n\cdot K)\), linear in \(n\) — which is exactly why it's the metric computed live inside every K-Means iteration, while Silhouette is reserved for offline evaluation.
The honest trade-off. Silhouette Score is more informative than WCSS (it captures inter-cluster separation, not just intra-cluster tightness) but strictly more expensive to compute. Good practice: use WCSS during the algorithm's iterations, and Silhouette afterwards, on a sample, to sanity-check and choose K.
21 · the question we deferred all class

Choosing the value of K

Back in Section 10 we assumed K was already known. Here's how you actually get there — combining everything from today.

Elbow method — sharp bend at K=3, then flattening. WCSS: 227.8 → 111.6 → 37.1 → 20.6 → 17.0 → 13.8 → 10.5
Silhouette curve — peaks at K=3 (0.589), then declines: 0.481 → 0.589 → 0.533 → 0.449 → 0.401 → 0.332
Both methods agree. The elbow method finds its sharpest bend at K=3; the Silhouette curve independently peaks at K=3. When two different metrics — one purely intra-cluster (WCSS), one intra and inter (Silhouette) — agree on the same K, that's strong evidence K=3 reflects real structure, not an artefact of one metric's blind spot.

The priority order for choosing K, in practice

1
Run the Elbow method first — cheap, fast, gives a shortlist of plausible K values (the bend, plus one on either side).
2
Confirm with Silhouette Score on that shortlist — it catches cases where WCSS's elbow is ambiguous or where clusters look tight but overlap badly.
3
Apply the business constraint last. ClusterMart's marketing team guessed 4 segments (Section 3) — but the data says 3. If marketing genuinely can't operate with 3 (needs a specific number of campaigns), that's a valid reason to move slightly off the statistical optimum — but it should be a deliberate override, not the starting point.
Never choose K by minimising WCSS directly. Section 14 already proved WCSS keeps falling all the way to zero at K=n. The elbow — the point of diminishing returns — is the signal, never the raw minimum.

Unsupervised learning discovers structure in \(X\) alone — no \(y\) required, because none exists.

Distance defines "similar"

Euclidean distance for continuous numeric features — K-Means' default and today's choice.

Provably the point that minimises WCSS for a fixed cluster membership.

Assign → update → repeat

K-Means alternates two steps that each only decrease WCSS, guaranteeing convergence.

Intra-cluster only — always falls with K, never chooses K by itself.

Silhouette closes the gap

Folds in inter-cluster separation, per point — at real \(O(n^2)\) cost, so sample it.

The one-sentence mental model

K-Means alternates between guessing where the centres are and re-averaging them toward whoever's actually nearby — repeating until nobody wants to switch sides, and always converging because every step can only tighten the clusters, never loosen them.
