01 · quick recap

The 4 methods, in one line each

Full theory is in Class 07. Here's just enough to follow the code.

MethodCore idea
IQRA point is an outlier if it's too far below Q1 or above Q3, on one feature at a time.
Elliptic EnvelopeFit an ellipse (mean + covariance) around the "normal" data; points far from its center (by Mahalanobis distance) are outliers.
Isolation ForestRandomly split the data with many trees; points that get isolated into their own leaf quickly (few splits) are outliers.
Local Outlier Factor (LOF)Compare a point's local density to its k nearest neighbors' density; a point sitting in a much sparser neighborhood than its neighbors is an outlier.

The dataset — used EVs

Same business framing as the Cars-24 regression classes: a used-EV listing dataset, 2 features — Mileage and Price. Same dataframe is reused across all 4 methods so results are directly comparable.

import numpy as np import pandas as pd import matplotlib.pyplot as plt import seaborn as sns df = pd.read_csv('AnomalyDetection.csv') plt.scatter(df.Mileage, df.Price) plt.xlabel('Mileage'); plt.ylabel('Price')
Why anomaly detection hereA listing with an unusually low price for its mileage (or vice versa) is exactly the kind of "few and different" point these 4 methods are built to catch — a pricing error, a damaged vehicle, or a data-entry mistake.
03 · code

IQR

import numpy as np def outlier_indices(x): Q1, Q3 = np.percentile(x, [25, 75]) IQR = Q3 - Q1 lower_bound = Q1 - (1.5 * IQR) upper_bound = Q3 + (1.5 * IQR) outlier_index = np.where((x < lower_bound) | (x > upper_bound)) return outlier_index outlier_indices(df['Mileage']) outlier_indices(df['Price']) df['Mileage'].iloc[outlier_indices(df['Mileage'])[0]]
LineWhat it does
Q1, Q3 = percentile(x, [25,75])the box edges of a boxplot, on one column
lower_bound / upper_boundfixed cutoffs, 1.5×IQR outside the box
np.where(x < lower | x > upper)row positions that fall outside those cutoffs
One feature at a timeRun separately on Mileage and Price — a car normal on both individually can still be a joint outlier (low mileage and high price together). IQR can't see that; the other 3 methods, working on both columns at once, can.
04 · code

Elliptic Envelope

import numpy as np from sklearn.covariance import EllipticEnvelope elpenv = EllipticEnvelope(contamination=0.5, # fraction assumed to be outliers random_state=1) pred = elpenv.fit_predict(df) # -1 = outlier, 1 = inlier df['is_outlier_ee'] = pred df[df['is_outlier_ee']==-1] # inspect the outliers plt.scatter(df.Mileage, df.Price, s=40, c=df['is_outlier_ee'])
ArgumentMeaning
contamination=0.5tell the model to expect (here) an unusually high 50% of rows as outliers — set high just to make the split visible in this small demo
fit_predict(df)fit the ellipse and label every training row in one call

07 · the real distinction

Two different questions

The code so far only answers one question. There's a second, different one it doesn't touch yet.

Outlier detection
"Among the rows I already have, which ones are weird?" fit_predict(df) — fit and label the same data in one call.
vs
Novelty detection
"Here's a car that just came in — is it weird, compared to what I've already seen?" Fit once on known-good data, then predict() on new rows, one at a time, as they arrive.
Same math, different questionEvery method still scores a point and compares it to a threshold. The only thing that changes is whose point is being scored — a training row, or a fresh one that showed up after fitting.
08 · why 2 of the 4 just work

Why Elliptic Envelope & Isolation Forest predict() new points natively

Both finish fitting with a complete, self-contained rule — evaluating it on a new point needs nothing but the point's own feature values.

MethodWhat fitting producesScoring a point x
Elliptic Envelopea center (mean) and a covariance matrix, describing the "normal" ellipseMahalanobis distance of x from that center — just arithmetic on x and the fitted numbers
Isolation Foresta fixed set of already-built random treesdrop x down every tree, average how many splits it took to isolate it
The key propertyNeither rule cares where x came from. A training row and a brand-new row are scored by the exact same formula/trees — so predict() on new data works immediately after fit(), no extra flag needed.
09 · the one exception

Why LOF needs novelty=True

LOF's score for a point is only defined relative to its neighbors — and "neighbors" only makes unambiguous sense within one fixed set of points.

1

For a training row, its 20 nearest neighbors (n_neighbors=20) are just other training rows — already sitting right there. fit_predict scores every row this way in one pass. This is the default, novelty=False.

2

For a genuinely new row, there's a real decision to make: find ITS 20 nearest neighbors — from where? sklearn's answer is to search inside the training data the model remembers. That's a materially different computation than step 1, done for a point the model has never scored before.

3

sklearn refuses to let that happen by accident. With novelty=False (the default), .predict() simply does not exist on the fitted object:

LocalOutlierFactor(n_neighbors=20).fit(X_train).predict(X_test) # AttributeError: 'LocalOutlierFactor' object has no attribute 'predict'
In shortElliptic Envelope and Isolation Forest's scoring rule was always "a function of x alone" — new points were never a special case. LOF's scoring rule is "a function of x and its neighborhood" — scoring a genuinely new point is a different operation from scoring a training point, so sklearn makes you opt in explicitly before it will do it.
10 · what actually changes

Setting novelty=True

from sklearn.neighbors import LocalOutlierFactor lof = LocalOutlierFactor(n_neighbors=20, contamination=0.025, novelty=True) lof.fit(X_train) # fit once, on data believed to be normal lof.predict(X_test) # now available: score new, unseen rows
novelty=predict() / decision_function() / score_samples()fit_predict()Intended use
False (default)not availableyes — the normal way to use LOFfind outliers within one fixed dataset
Trueavailable, on new datatechnically callable, but wrong to use herescore future new points against a fitted reference
One more catch, once novelty=TrueFit only on clean/reference data (not data you suspect already has outliers in it) — and call predict() only on new rows, never on the training rows themselves. A training row fed back into predict() would find itself (distance 0) sitting in the stored training set and count that as its own nearest neighbor — making it look artificially normal. sklearn keeps the training rows' real scores separately, in the negative_outlier_factor_ attribute, for exactly this reason.
11 · where the cutoff comes from

contamination → threshold, at fit time

Same recipe for all 3 model-based methods — only the "score" formula changes.

1

Fit the model on the training data (mean+covariance / trees / neighbor-distances).

2

Compute every training row's raw anomaly score using that fitted model.

3

Sort those scores. contamination says what fraction should end up flagged — so the cut line is placed exactly at that percentile of the sorted scores.

4

That cut line is saved as the model's threshold — a single fixed number, kept for later.

MethodRaw scorecontamination exampleThreshold, in words
Elliptic EnvelopeMahalanobis distance from the fitted center0.5the distance below which the closest 50% of rows sit
Isolation Forestaverage path length to isolate the point (shorter = more anomalous)0.03the path-length cutoff below which the most-isolated 3% sit
LOFlocal outlier factor (density of neighbors ÷ density of the point)0.025the LOF value above which the sparsest 2.5% sit
The pointcontamination never touches the new-point calculation directly — its only job is to fix this one threshold number, once, during fit.
12 · using it on a new point

Scoring a brand-new point

Once the threshold exists, predicting is just: compute the same score for the new point, then compare.

Same flow for Elliptic Envelope, Isolation Forest, and LOF (novelty=True) — only "score(x)" differs.
Methodscore(new point x)Compared against
Elliptic Envelopex's Mahalanobis distance from the (already fitted) centerthe distance threshold fixed at fit time
Isolation Forestdrop x down the (already built) trees, average the path lengththe path-length threshold fixed at fit time
LOF (novelty=True)find x's 20 nearest neighbors inside the stored training data, compute x's LOF from themthe LOF threshold fixed at fit time
Easy way to remember itFitting answers "how unusual does a point have to be, to count as the worst contamination% ?" — and freezes that answer as one number. Predicting just asks "is this point's score past that frozen number?" Nothing about the new point changes the threshold itself.

The one thing to remember

Elliptic Envelope and Isolation Forest finish fitting with a rule that only needs a point's own feature values — so scoring a new point is no different from scoring a training point, and predict() is available immediately. LOF's rule needs a neighborhood to mean anything — scoring a genuinely new point means searching for its neighbors inside the stored training data, a step training-time scoring never had to do. sklearn hides that step behind novelty=True so it only happens when you actually ask for it. Once fit, all three freeze one threshold number from contamination; predicting a new point is always just "compute its score, compare to that frozen number."
