00 · quick recap of class 08

The PCA chain, so far

Five ideas, in the order we built them last class. Today's whole class sits on top of the last one.

Step 1
Standardize: X → Xstd, so no feature dominates just because its raw numbers are bigger.
Step 2
Pick a candidate unit direction w and project every point onto it: z = wᵀXstd — one number per point.
Step 3
Ask: which w makes Var(z) largest? Expanding the algebra forces a matrix to appear: Var(z) = wᵀΣw, where Σ is the covariance matrix.
Step 4
Maximizing wᵀΣw needs a length constraint wᵀw = 1 (else the score grows without bound) → solved with a Lagrange multiplier.
Step 5
Solving produces, unforced: Σw = λw — the eigenvector equation. w = eigenvector of Σ, λ = eigenvalue = the variance captured along w.
where class 08 ended
$$\Sigma w = \lambda w \qquad\qquad \lambda = \text{Var}(z) \qquad\qquad \boxed{\text{max } \lambda \Rightarrow \text{max variance direction} = \text{PC1}}$$
Today's four open questions Class 08 told us how to find PC1. It left four things unanswered — exactly the four sections of today's class: (1) what does the eigenvector w actually mean? (2) once PC1 is taken, how do we find PC2, PC3, … without repeating PC1? (3) with d possible components, how many should we actually keep? (4) what does PCA quietly throw away?
01 · question 1

A principal component direction is a recipe over your features

"w is a unit vector" is correct but unhelpful. Here's what it actually represents.

Go back to Class 08's running example: 6 students, standardized hours studied (x₁) and standardized problems solved (x₂). We solved Σw = λw and found:

PC1 for our dataset
$$w = \begin{pmatrix}0.707\\0.707\end{pmatrix} \qquad z_i = w^\top x_i = 0.707\,x_{i1} + 0.707\,x_{i2}$$

Read the right-hand side literally: the projected score for every student is 70.7% of their (standardized) hours studied, plus 70.7% of their (standardized) problems solved. That's not an abstract "angle" — it's a weighted blend, a recipe, built entirely from the columns you already had. PCA never invents a new measurement; it only tells you how to combine the ones you have.

w is literally the vector sum of its two components: 0.707 units along the x₁ axis, plus 0.707 units along the x₂ axis. Every entry of the eigenvector is "how much of that original feature goes into the mix."
The one-line takeaway PC1 = w₁x₁ + w₂x₂ + … + w₌x₌ — a linear combination of the original features, nothing more exotic. The coefficients (w₁, w₂, …) come straight out of the eigenvector, and they tell you exactly how much weight PCA gave to each original column when building this new axis.
Sign is arbitrary — recall Class 08, Section 07 If w is an eigenvector, so is −w — same eigenvalue, same line, just the arrow flipped (a scalar multiple never leaves the line it's on). So a computer library might hand you w = (−0.707, −0.707) instead — same PC1, same variance captured, only the sign convention differs. Don't read meaning into which way the arrow points; read meaning into which line it's on and how big each coefficient is.
02 · scaling it up

The same idea for d features, not just 2

Nothing changes conceptually going from 2 features to 50 — only the length of the recipe.

general form
$$w = \begin{pmatrix}w_1\\w_2\\\vdots\\w_d\end{pmatrix} \qquad\qquad PC_1 = w_1x_1 + w_2x_2 + \cdots + w_dx_d$$

Concretely: take a 3-feature version of our dataset (standardized hours studied x₁, practice problems x₂, assignment score x₃). Solving Σw = λw on the 3×3 covariance matrix gives three eigenvectors — one full "recipe" per component:

ComponentRecipe (loadings on x₁, x₂, x₃)λ (variance captured)Share of total variance
PC10.586 x₁ + 0.560 x₂ + 0.587 x₃2.79193.0%
PC20.410 x₁ − 0.829 x₂ + 0.382 x₃0.1846.1%
PC3−0.700 x₁ − 0.017 x₂ + 0.714 x₃0.0250.8%

Notice PC1's coefficients here are all positive and close to equal (0.586, 0.560, 0.587) — because these three features are all strongly, positively correlated (a student who studies more also solves more problems and scores higher). PC1 has effectively become "overall academic engagement," a near-equal blend of all three. That's exactly what "linear combination of input features" cashes out to in practice.

Where this is heading When 3 correlated features blend into one clean, nameable idea, that's the friendly case. With 50 features and messier correlations, the blend stops having one clean name — that's Limitation 1, in Section 09.
03 · question 2, part A

We have PC1. What's next?

PC1 = the eigenvector with the largest λ. Naively repeating the same search for a "second-best direction" has an obvious failure mode.

The problem, stated plainly If we just re-run "maxw wᵀΣw subject to wᵀw=1" a second time with no other change, the maximizer is still PC1 — nothing in the problem stops it from picking the same winning direction again.
Without an extra rule, the search has no reason to avoid landing back on PC1, or anywhere close to it.

So we need a new rule that rules PC1 back out — and the rule PCA imposes is the one we've been building toward all class: look only among directions perpendicular to PC1.

PC2's optimization problem
$$\max_{w_2} \; w_2^\top \Sigma w_2 \qquad \text{s.t.} \qquad w_2^\top w_2 = 1 \quad\text{and}\quad w_2^\top w_1 = 0$$
ConstraintMeaning
w₂ᵀw₂ = 1w₂ is a unit direction (same rule as before)
w₂ᵀw₁ = 0new: w₂ is perpendicular (orthogonal) to w₁ — the dot product of two vectors is 0 exactly when they meet at 90°
Why perpendicular, not "just different"?Perpendicular directions carry independent information — none of the spread PC2 captures overlaps with what PC1 already captured. Any non-perpendicular "second choice" would partially re-describe what PC1 already told us, which wastes a dimension. We'll see this fall out as a forced consequence, not an assumption, in the next section.
04 · question 2, part B

Proof — orthogonality is forced, not assumed

Same machinery as Class 08 (Lagrange multipliers) — one extra constraint, one extra multiplier. Watch what falls out.

Lagrangian with two constraints
$$\mathcal{L}(w_2,\lambda,\mu) = w_2^\top\Sigma w_2 \;-\; \lambda(w_2^\top w_2 - 1) \;-\; \mu\,(w_2^\top w_1)$$
StepDo thisResult
1Differentiate ℒ w.r.t. w₂, set to 0 (same two derivative rules as Class 08 Section 16)$2\Sigma w_2 - 2\lambda w_2 - \mu w_1 = 0$
2Left-multiply the whole equation by w₁ᵀ$2w_1^\top\Sigma w_2 - 2\lambda w_1^\top w_2 - \mu w_1^\top w_1 = 0$
3Apply what we already know: w₁ᵀw₂=0 (constraint) and w₁ᵀw₁=1 (unit norm)$2w_1^\top\Sigma w_2 - \mu = 0$
4Σ is symmetric, so w₁ᵀΣ = (Σw₁)ᵀ; and from Class 08, Σw₁=λ₁w₁$w_1^\top\Sigma w_2 = (\lambda_1 w_1)^\top w_2 = \lambda_1(w_1^\top w_2) = \lambda_1 \cdot 0 = 0$
5Substitute back into Step 3$2(0) - \mu = 0 \;\Rightarrow\; \boxed{\mu = 0}$
6Put μ=0 back into Step 1$2\Sigma w_2 - 2\lambda w_2 - 0 = 0 \;\Rightarrow\; \boxed{\Sigma w_2 = \lambda w_2}$
What just happened The orthogonality multiplier μ — whose whole job was to enforce "stay perpendicular to PC1" — solved out to exactly zero. It vanishes on its own; we never had to force it. And what's left, Σw₂=λw₂, is again the plain eigenvector equation from Class 08. PC2 is also just an eigenvector of Σ — the perpendicularity constraint didn't change the type of equation we had to solve, it only restricted which eigenvector counts as a valid candidate (any eigenvector already perpendicular to w₁ automatically satisfies it).

Since Σ is symmetric, its eigenvectors for different eigenvalues are automatically perpendicular to each other (a standard fact about symmetric matrices — proved in the optional box below). So among all remaining eigenvectors of Σ, we simply pick the one with the next-largest λ, and orthogonality to PC1 comes for free:

PC2
$$w_2 = \text{eigenvector of } \Sigma \text{ with the 2}^{\text{nd}}\text{-largest eigenvalue } \lambda_2$$
Optional — why symmetric matrices automatically give perpendicular eigenvectors

Let v₁, v₂ be eigenvectors of a symmetric matrix Σ with different eigenvalues λ₁ ≠ λ₂.

StepDo thisResult
1Start from Σv₁=λ₁v₁; left-multiply by v₂ᵀ$v_2^\top\Sigma v_1 = \lambda_1(v_2^\top v_1)$
2Σ symmetric ⇒ v₂ᵀΣ = (Σv₂)ᵀ = (λ₂v₂)ᵀ$v_2^\top\Sigma v_1 = \lambda_2(v_2^\top v_1)$
3The left-hand sides of steps 1 and 2 are identical ⇒ the right-hand sides must be equal$\lambda_1(v_2^\top v_1) = \lambda_2(v_2^\top v_1)$
4Rearrange$(\lambda_1-\lambda_2)(v_2^\top v_1) = 0$
5Since λ₁ ≠ λ₂, the first factor is nonzero, so the second must be 0$\boxed{v_2^\top v_1 = 0}$
This is exactly why Σ's covariance-matrix structure (always symmetric) is what guarantees perpendicular principal components — it isn't a special property we build into PCA by hand, it's inherited for free from Σ being symmetric.
05 · generalizing again

Every principal component is perpendicular to every other one

The same argument in Section 04 repeats for PC3, PC4, … each time adding one more orthogonality constraint.

ComponentConditions it must satisfy
PC1 = w₁w₁ᵀw₁ = 1
PC2 = w₂w₂ᵀw₂ = 1  and  w₂ᵀw₁ = 0
PC3 = w₃w₃ᵀw₃ = 1  and  w₃ᵀw₁ = 0,  w₃ᵀw₂ = 0
PCk = wkwkᵀwk = 1  and  wkᵀwj = 0 for every j < k

Let's actually verify this — not just assert it — on a real 3-feature dataset (the study-hours/practice/assignment-score example from Section 02). Its three eigenvectors, arranged as columns of a matrix W = [w₁ w₂ w₃]:

Sketch only (three mutually perpendicular directions can't be drawn at true angles on a flat page) — the actual 90° angles are confirmed numerically below, not by the picture.
the actual proof for this dataset — WᵀW
$$W^\top W = \begin{pmatrix}0.586 & 0.410 & -0.700\\0.560 & -0.829 & -0.017\\0.587 & 0.382 & 0.714\end{pmatrix}^{\!\top}\!\!\begin{pmatrix}0.586 & 0.410 & -0.700\\0.560 & -0.829 & -0.017\\0.587 & 0.382 & 0.714\end{pmatrix} = \begin{pmatrix}1 & 0 & 0\\0 & 1 & 0\\0 & 0 & 1\end{pmatrix}$$
Reading this matrixThe diagonal being all 1's confirms every wk has unit length. The off-diagonal zeros confirm every pair is perpendicular — w₁ᵀw₂=0, w₁ᵀw₃=0, w₂ᵀw₃=0, all simultaneously, computed from real numbers, not assumed. W is what's called an orthonormal matrix — its columns form a brand-new set of coordinate axes for the same space, just rotated to line up with the data's actual spread.
The picture to keep

PCA doesn't hunt for k separate "best directions" independently. It builds one full rotation of the axes — d perpendicular directions total (for d original features), ranked by how much variance each one captures. You then keep the first k of that ranked list. Nothing about a lower-ranked PC changes if you decide to keep more or fewer of them; they were all found together, once.

06 · optional, self-read

What if λ₁ = λ₂? Is perpendicularity still automatic?

Short answer: no — not automatically. But it's always achievable, and PCA always achieves it. The reasoning is genuinely different from Section 04's proof, so it's worth pulling apart carefully rather than waving at "the same symmetric-matrix magic."

Where the Section 04 proof actually stops working

Look at the last two steps of that proof again:

$$(\lambda_1-\lambda_2)(v_2^\top v_1) = 0 \;\;\xRightarrow{\;\div(\lambda_1-\lambda_2)\;}\;\; v_2^\top v_1 = 0$$

Getting to v₂ᵀv₁=0 required dividing both sides by (λ₁−λ₂) — legal only because that factor is nonzero. If λ₁=λ₂, that factor is zero, and the equation collapses to 0 × (v₂ᵀv₁) = 0 — true regardless of what v₂ᵀv₁ actually equals. The proof simply goes silent once eigenvalues tie. So this needs its own argument, not an extension of Section 04's.

Proof that it really isn't automatic

Take the repeated-eigenvalue matrix from before and grab two different, both perfectly valid eigenvectors for λ=2:

a degenerate case
$$\Sigma = \begin{pmatrix}2 & 0 & 0\\0 & 2 & 0\\0 & 0 & 0.3\end{pmatrix} \qquad \lambda = (2,\ 2,\ 0.3)$$
VectorΣvEigenvector for λ=2?
v = (1, 0, 0)(2, 0, 0) = 2vyes
v′ = (0.6, 0.8, 0)(1.2, 1.6, 0) = 2v′yes
now check whether they're perpendicular
$$v^\top v' = (1)(0.6) + (0)(0.8) + (0)(0) = 0.6 \;\ne\; 0$$
Not perpendicular — and both are still 100% legitimatev and v′ are each completely valid eigenvectors for λ=2. Neither is "more correct." But their dot product is 0.6, not 0. So two arbitrary eigenvectors sharing an eigenvalue are not automatically orthogonal — if you just grabbed any two eigenvectors a solver happened to return for a repeated eigenvalue, unlucky. Something else has to be actively ensuring perpendicularity here — it isn't falling out of the algebra for free the way it did in Section 04.

So how does PCA still guarantee it?

By choosing, not by accident. Every eigenvector for λ=2 — v, v′, and every other direction like them — lives inside one 2-dimensional plane (the x₁–x₂ plane here; the eigenvalue's multiplicity is 2, so its full eigenspace is 2-dimensional). That plane is an ordinary 2D vector space in its own right, and every 2D vector space has infinitely many orthonormal bases — pick any unit vector inside the plane, rotate it 90° for the second, done. Both stay inside the plane, so both stay eigenvectors for λ=2, and by construction their dot product is exactly 0:

Pick any unit vector in the plane......rotate 90° within the plane for the secondDot product
u₁ = (1, 0, 0)u₂ = (0, 1, 0)0 — perpendicular
u₁ = (0.799, 0.602, 0)u₂ = (−0.602, 0.799, 0)0 — perpendicular
The actual mechanism, stated precisely Orthogonality between eigenvectors of a repeated eigenvalue is not automatic (Section 04's algebra has nothing to say about it) — it's constructed, by picking an orthonormal basis of the shared eigenspace (a standard Gram-Schmidt step). That construction always succeeds, because every subspace has an orthonormal basis. This is exactly what the spectral theorem for real symmetric matrices guarantees: since Σ is always symmetric, it always has a complete orthonormal set of eigenvectors — tied eigenvalues or not. It is a standard property, just a different one from Section 04's — and yes, it's guaranteed every time. numpy's eigh / sklearn's PCA perform this construction for you automatically; you never do the Gram-Schmidt step by hand.

One consequence worth flagging: since any orthonormal basis of that plane works equally well, the specific pair PCA hands you for a tied eigenvalue is not unique. Rotate both u₁ and u₂ together by any angle within the plane and you get an equally valid, equally orthogonal, equally-variance-capturing PC1/PC2 pair (exactly what the two rows of the table above show — same plane, different rotation, both perpendicular). A re-run with a different library, or the same library on a barely-different dataset, can rotate that particular pair without changing how much variance either one captures.

Are two eigenvalues of Σ ever actually equal in practice?

SituationExactly equal eigenvalues?
Real-world, continuously-valued data with no built-in symmetry — almost everything you'll actually work withessentially never — distinct with probability 1
Data with a genuine structural symmetry — e.g. truly isotropic spread in 2+ directions, a perfect circle/sphere of pointsyes, exactly, by construction
Toy/synthetic datasets built to demonstrate this case — like Σ above, or Section 10's circle exampleyes, by design
A far more common cousin of this problemExact ties are rare, but near-ties (λ₁ and λ₂ close but not equal) are not — they happen whenever two directions happen to carry nearly the same variance. The eigenvectors are still uniquely defined and perfectly perpendicular in that case (Section 04's proof applies fine, since λ₁≠λ₂ is still technically true) — but which one gets labeled "PC1" and which "PC2" can flip with tiny changes to the data or a different random seed, since both are competing for essentially the same amount of variance. Worth remembering if two of your explained-variance-ratio numbers (Section 07) ever come out suspiciously close together.

Geometrically: a perfect circle of data (equal spread in every direction) has no unique "long axis" — this is precisely the case in Section 10's circle example, where you'll see the exact λ₁=λ₂=4.909 tie again.

07 · question 3, part A

Explained variance ratio

We now have d perpendicular components, ranked by λ. The next question: how much of the "story" does each one actually tell?

explained variance ratio (EVR)
$$EVR_k = \dfrac{\lambda_k}{\sum_{j=1}^{d}\lambda_j}$$

The denominator, ∑λj, is the total variance in the (standardized) dataset — every eigenvalue added up. EVRk is simply "what fraction of that total does component k alone account for." Stack them up in ranked order and you get the cumulative explained variance:

cumulative explained variance
$$CEVR_k = \sum_{j=1}^{k} EVR_j$$

Worked example — 6 real (standardized) features, eigen-decomposed:

ComponentλEVRCumulative
PC12.10535.08%35.08%
PC21.84030.67%65.75%
PC31.06217.69%83.44%
PC40.72112.02%95.46%
PC50.1782.97%98.43%
PC60.0941.57%100.00%
Total (d=6)6.000100%
Gold/slate/grey bars = EVR (scree plot), read on the left. Teal line = cumulative variance, crossing the 95% mark (dashed coral) right at PC4 (circled).
08 · question 3, part B

So how many components should I actually keep?

Three practical rules, all reading the same chart above — pick whichever fits the situation.

1 · Variance threshold

Decide upfront how much of the original information you're willing to keep — typically 90–95% — and keep the smallest k whose cumulative EVR clears that bar.

In our example: 95% is crossed exactly at k=4 (95.46%). This is the most common rule used in practice — simple, and directly tied to "how much did we actually lose."
2 · Elbow method

Look at the scree plot (the bars) and find where the bars stop dropping sharply and start flattening out — the "elbow."

Here: PC1→PC2 drops gently (35.1%→30.7%), then a sharper drop into PC3–PC4, then a visibly flat tail from PC5 onward. The elbow sits around k=4 too — components after this add very little each.
3 · Kaiser rule (standardized data only)

Since every standardized feature has variance exactly 1, the average eigenvalue is always 1. Keep only components with λ > 1 — i.e. components carrying "more than an average feature's worth" of variance.

Here: λ=2.105, 1.840, 1.062 all exceed 1; λ=0.721 doesn't → suggests k=3. A stricter, more conservative answer than the other two rules — good as a sanity floor, not usually the final word.
These rules can (and will) disagree Above, threshold and elbow both point to k=4; Kaiser points to k=3. That's normal — there's no single "mathematically correct" k. In practice: start with the 90–95% threshold rule as a default, sanity-check it against the scree plot's elbow, and let the downstream task (does a model trained on k components perform well enough? is 2–3 needed purely for visualization?) make the final call.
Special case — visualizationIf the only goal is to plot the data, k is forced to 2 or 3 regardless of variance retained, even if that only captures 65.75% (k=2, from our table). You're trading information for the ability to literally see the data — a different goal from modeling, with a different answer.
09 · question 4, limitation 1

Limitation — interpretability gets harder, fast

Section 02 showed a friendly case: 3 correlated features blending into one nameable idea. Real datasets are rarely that clean.

Take a 6-feature lending dataset — Age, Income, Credit Score, Loan Amount, Tenure, Num. Transactions — the same eigen-decomposition as Sections 07–08. Here is PC1's actual, real recipe:

PC1's real loadings — not simplified for teaching
$$PC_1 = -0.345\,\text{Age} - 0.564\,\text{Income} + 0.634\,\text{CreditScore} - 0.063\,\text{LoanAmount} + 0.240\,\text{Tenure} - 0.315\,\text{NumTxns}$$
Now try to name PC1 in one word Unlike Section 02's example, the signs here don't agree, and the weights don't cleanly track one intuitive idea. Is PC1 "creditworthiness"? It's pulled down by Income and Num. Transactions having negative loadings, which fights that story. This is the real, common case — most PCs in practice are unnamed blends, not clean concepts.

What a unit "means"Exactly what it says — Age in years, Income in ₹A moving blend of 6 different units and signs

It becomes a real limitation specifically when a human needs to read and justify what a component means — audits, medical decisions, credit decisions, or just explaining results to a non-technical stakeholder.
10 · limitation 2

Limitation — PCA does not preserve neighborhoods

The sharpest limitation of all, and the one that sets up next class. PCA optimizes for one thing only — global variance. It was never asked to keep "who is near whom."

The core issueTwo points that are very close together in the original high-dimensional space can land far apart after projection — and two points that were far apart can land right on top of each other. PCA has no constraint that prevents either.

Case 1 — a curved manifold collapses unevenly

12 points, evenly spaced (30° apart) around a perfect circle in 2D. By symmetry, every direction has equal variance (λ₁=λ₂=4.909 — exactly Section 06's degenerate case), so PCA arbitrarily picks one diameter as PC1 — here, the vertical axis:

Original 2D: points 0 and 6 are diametrically opposite — the farthest apart two points can be on this circle.
After projecting onto PC1: points 0 and 6 land on the exact same spot (z=0.00). Maximally far → identical. Also notice pairs like 2 & 4 collapse together despite being 60° apart on the circle.

Local neighborhoods are not preserved consistently, even within the same dataset.

Case 2 — two real clusters merge into one

Two clearly separated clusters in 2D. The separation between them happens to sit along the low-variance direction, while a wide, uninformative spread runs along the high-variance direction:

Two obviously separate clusters — the gap between them (vertical) is small compared to each cluster's own wide horizontal spread. PC1 aligns with the wide, uninformative horizontal spread.
PC1 (kept) tangles the two clusters completely. PC2 (thrown away, only 14.7% of variance) is exactly the axis that would have kept them apart.
The lesson "High variance" and "the direction that matters for your task" are not the same thing, and PCA has no way to know which one you actually need — it only ever optimizes the first. A direction that perfectly separates two real, meaningful groups can be thrown away simply because, numerically, it doesn't happen to spread the data out very much.
Where this is heading, next classBoth cases here share one root cause: PCA is a strictly linear, strictly global-variance method. It has no notion of "who is near whom" locally. Next class's method (t-SNE) is built from the ground up to directly optimize for exactly that — keeping neighbors as neighbors — at the cost of everything PCA is good at (global structure, speed, an exact formula, and reconstructability). Preview visible on the whiteboard already: P(B|A), P(C|A), … neighbor probabilities instead of variance.
11 · rounding out the picture

Other limitations, briefly

Only linear combinations

Every PC is a straight-line blend, w₁x₁+w₂x₂+…. If the true structure is curved (a spiral, a sphere, an S-shape), no linear combination of the raw features can describe it well, no matter how many components you keep.

The circle example in Section 10 is the simplest possible case of this.
Sensitive to outliers

Variance is a squared quantity — a single extreme point contributes disproportionately to Σ, and can single-handedly rotate PC1 toward itself.

Same root cause as why mean and standard deviation (not median/IQR) are outlier-sensitive — variance inherits that.
Needs (roughly) linear correlation

Σ only captures pairwise linear correlation between features. Two features with a strong but curved (non-linear) relationship can show near-zero covariance, and PCA will treat them as unrelated.

PCA can miss real structure that isn't shaped like a straight-line relationship.
12 · question 5

PCA and categorical variables

Everything so far — variance, covariance, eigenvectors — assumes continuous, numeric features. Real datasets usually aren't purely that.

Why PCA struggles directly on categoriesVariance and covariance are built for continuous, ordered quantities — "how far, on average, from the mean." A category like City ∈ {Delhi, Mumbai, Pune} has no natural ordering or distance ("is Pune numerically between Delhi and Mumbai?" is meaningless), so "the variance of City" isn't a well-defined idea the way "the variance of Age" is.

The standard fix: encode, then apply PCA on the numeric result

Specialized cousins of PCA exist specifically for this problem — worth knowing the names exist, not worth deriving:

MethodBuilt forRough idea

In practice, most teams reach for "encode + plain PCA" (Section above) long before reaching for MCA/FAMD — those are seen far more often in academic/statistics contexts than in typical industry ML pipelines. Tree-based models (which handle raw categories natively, no PCA needed at all) are often the more common industry answer when categorical structure genuinely matters.
13 · question 6

Reconstruction error — how much did we actually lose?

Explained variance ratio told us this in percentages. Reconstruction error tells us the same thing in the original units, point by point.

X is projected down to k components (Z, the compressed representation), then projected back up to d dimensions (X̂, the best possible reconstruction from only k components). The gap between the original and the rebuilt version is the price paid for compression.
encode / decode
$$Z = XW_k \qquad\qquad \hat X = ZW_k^\top$$

Here Wk is the d×k matrix of the first k eigenvectors (as columns). Encoding projects onto those k directions; decoding uses the same directions to map back into the original d-dimensional space — it's the only sensible "undo," since Wk is the one matrix we actually have.

reconstruction error (MSE)
$$MSE = \dfrac{1}{nd}\sum_{i=1}^{n}\sum_{j=1}^{d}(X_{ij}-\hat X_{ij})^2$$

Average squared difference between every original entry and its rebuilt counterpart, over the whole dataset. Small MSE → X̂ is a faithful stand-in for X using only k numbers per row instead of d.

The exact relationship — verified numerically, not just approximately For standardized data, MSE(k) = (λk+1 + λk+2 + … + λd) / d — the average of exactly the eigenvalues you dropped. Equivalently: MSE(k) = (1 − CEVRk) when variance is expressed per-feature. This is not a coincidence: explained variance ratio and reconstruction error are two ways of reporting the exact same number. Checked directly: at k=2, dropped eigenvalues sum to 2.055, divided by d=6 gives 0.3425 — matches the measured MSE of 0.3417 up to ordinary sampling noise.
15 · putting a number on "good"

What counts as a good reconstruction error?

There is no universal "MSE below X is good" rule — a raw MSE value means nothing without context. Here's how to actually read it.

Why a bare MSE number is meaningless on its own MSE = 0.5 sounds bad — until you realize the total variance in a d-feature standardized dataset is exactly d (each feature contributes variance 1). MSE = 0.5 out of a total of 100 (d=100) is excellent; MSE = 0.5 out of a total of 2 (d=2) is terrible. Always read MSE relative to d, or — easier — just read the cumulative explained variance ratio directly; it's the same information already normalized for you.
≥ 95%
CEVR — very safe default
90–95%
CEVR — common, reasonable trade-off
70–90%
CEVR — usable, inspect what's lost
< 70%
CEVR — significant information loss
Question to askWhy it changes the "acceptable" threshold
What's the downstream task?Feeding k components into a model that's cross-validated for performance → let validation accuracy decide k directly, not a fixed MSE rule
Is this for visualization?k is forced to 2–3 regardless of MSE — you accept whatever loss comes with that, because seeing the data is the entire point (Section 08)
Is this for compression / storage?Compare the MSE cost against how much smaller k makes your data — a direct trade-off you can quantify
Are individual points' errors uneven?A low average MSE can hide a few points reconstructed very badly (Section 14's students 3 & 4) — check the per-point spread, not just the mean, when individual points matter
The practical rule of thumbDon't target a raw MSE number at all — target a cumulative explained variance (typically 90–95%), and let MSE be the report card that confirms you actually got there. The two are the same measurement in different units (Section 14), so picking k by one is picking k by the other.

Classes 08 + 09, one picture

Class 08 built the machine. Class 09 explained what it hands you, and where it quietly runs out of road.

Class 08
Standardize → project onto unknown w → Var(z)=wᵀΣw → constrain wᵀw=1 → Lagrange multiplier → Σw=λw falls out → λ=variance captured → pick max λ for PC1.
Today, Sections 01–02
Every eigenvector w is a linear combination of the original features — its entries are literal blending weights, not abstract angles.
Today, Sections 03–06
PC2's constrained optimization forces its Lagrange multiplier for orthogonality to exactly 0 — perpendicularity is a consequence of Σ being symmetric, not a rule we impose by hand. Holds for every PC, even under tied eigenvalues.
Today, Sections 07–08
EVRk=λk/∑λj turns eigenvalues into interpretable percentages; cumulative EVR plus a threshold (or elbow, or Kaiser) picks k.
Today, Sections 09–11
PCA optimizes variance only — components can become uninterpretable blends, curved/non-linear structure is invisible to a linear method, and local neighborhoods can be scrambled even while global variance is preserved.
Today, Section 12
Categorical features need encoding before PCA can touch them at all; PCA remains a numeric-variance method underneath.
Today, Sections 13–15
Reconstruction error X̂=ZWᵀ quantifies the same information loss EVR already reports — MSE(k) and (1−cumulative EVR) are the same number, two units.
The one-paragraph version of both classes

PCA rotates the coordinate axes to line up with the data's own spread, ranked by variance, with every new axis forced perpendicular to all the others — this isn't assumed, it falls directly out of maximizing wᵀΣw under a symmetric Σ. Each axis is a named-in-numbers blend of your original features. Keep the top few axes (by a variance-retained threshold, an elbow, or a downstream task's own judgment) and you get a faithful, compressed stand-in for your data — faithful in the one specific sense of "preserves overall spread," which is not the same as "preserves who was near whom," and not the same as "stays interpretable."

17 · looking ahead

Where we go next — t-SNE

Section 10's limitation is exactly next class's motivation.

PCA — this class
Linear. Deterministic (one exact answer via eigen-decomposition). Optimizes global variance. Gives you an exact formula you can reconstruct from. Blind to curved/non-linear structure and to local neighborhoods.
vs
t-SNE — next class
Non-linear. Stochastic (results vary run to run, optimized by gradient descent from a random start). Optimizes local neighbor similarity directly — its entire objective is "who was near whom." Built specifically for visualization; no simple reconstruction back to the original space.
The trade being madet-SNE will fix precisely the circle/clusters problem from Section 10 — points close in high-D will (by explicit design) stay close in the low-D picture — at the cost of everything that made PCA convenient: no closed-form solution, no simple "loadings," results that change between runs, and a picture whose absolute distances and cluster sizes should not be over-trusted. Same visualization goal as PCA's k=2/3 case (Section 08), pursued with an entirely different, entropy-and-probability-based mathematical toolkit.
